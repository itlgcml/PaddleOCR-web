# 用户注册与登录功能 · 后端设计

> 适用工程：`backend/`（JDK 8 + Spring Boot 2.7.18 + MyBatis-Plus 3.5.17 + Druid 1.2.28 + MySQL）
> 编写依据：现有 `ocr-common` / `ocr-client` / `ocr-dal` / `ocr-service` / `ocr-web` 分层与命名约定
> 目标：为 PaddleOCR-web 补齐"账号体系 + 组织架构（机构树）+ 角色体系 + 认证鉴权"

---

## 1. 现状分析

| 现状 | 说明 |
|---|---|
| 无用户实体 | `ocr-dal` 仅有 mapper 配置类，尚未出现任何 DO（`sql/` 目录为空） |
| 无认证链路 | 全项目搜索无 `auth / token / jwt / login / captcha` 相关代码，所有接口裸奔 |
| 已有基础设施 | `ApiResponse<T>` 统一响应、`ResultCode` 错误码、`BusinessException` + `GlobalExceptionHandler` 已就绪 |
| 已有数据层能力 | `MybatisPlusConfig`（分页）、`AuditMetaObjectHandler`（审计字段填充）、逻辑删除全局配置 `logic-delete-field: deleted` |
| 已有基础设施（续） | Druid 数据源、`map-underscore-to-camel-case`、`JacksonConfig`、`CorsConfig`（`/api/**`）、springdoc-openapi-ui |
| 前端待对接 | `frontend/src` 已有 `api / stores / router`，登录态可由 Pinia + 拦截器承载 |

**结论**：纯增量需求，不改动既有类，仅在约定模块内新增文件 + 在 `ResultCode`、`application.yml` 追加条目。

### 1.1 术语与实体关系约定

| 实体 | 关系 | 说明 |
|---|---|---|
| `sys_user`（用户表 = 员工表） | —— | **员工不单独建表**，用户即员工，`sys_user` 直接挂 `org_id`；账号-员工 1:1 分离对单账号体系是过度设计，未来若需"一人多机构/多账号"再引入 `sys_employee` |
| `sys_org`（机构表） | 机构 : 用户 = **1 : n** | 树形结构（`parent_id` + `ancestors` 祖先链）；一个机构多个员工，一个员工只属一个机构 |
| `sys_role`（角色表） | —— | 存储角色信息（编码 + 名称），内置 `ADMIN` / `USER` |
| `sys_user_role`（关联表） | 角色 : 用户 = **n : m** | 一个用户可绑多个角色，一个角色可绑多个用户 |

```
sys_org (1) ──< sys_user (n)                      # org_id 逻辑外键（1:n）
sys_user (m) ──< sys_user_role >── (n) sys_role   # n:m 关联表
```

## 2. 目标与范围

### 2.1 本期（V1）

1. 账号密码注册（用户名 + 邮箱 + 密码 + 可选所属机构）。
2. 账号密码登录，签发 JWT；登录出参带机构 + 角色信息。
3. 基于 JWT 的请求鉴权（白名单放行 + 全局拦截），**认证与拦截统一走 Spring Security 过滤器链**。
4. 获取当前登录用户 `/api/auth/me`、登出 `/api/auth/logout`。
5. 登录失败次数限制与账号锁定。
6. **机构管理**：树查询、增删改（删除校验子机构/在职员工）。
7. **角色管理**：分页查询、增删改（删除校验是否仍被用户绑定；内置角色保护）。
8. **用户-角色分配**：管理员给用户全量设置角色；用户机构调整。
9. **刷新令牌**：accessToken 2h + refreshToken 7d，`/api/auth/refresh` 静默续期（本期不轮换）。

### 2.2 明确不做（避免过度设计）

| 项 | 决策 | 理由 |
|---|---|---|
| ~~Spring Security 全量框架~~ | **改为引入（本次修订）** | 登录认证与请求拦截统一收口 Spring Security 过滤器链；早期"Filter + ThreadLocal + AOP 自研"方案废弃，理由见 §3 |
| 菜单/按钮级权限（`sys_menu` / `sys_role_menu`） | V2 预留 | 本期角色只做接口级鉴权 |
| 机构级数据隔离（数据权限） | V2 预留 | "我的 OCR 记录"只按 userId 过滤；机构数据范围隔离依赖 ancestors 方案，已预留 |
| 员工表与用户表分离 | 不做 | 见 §1.1 |
| ~~Redis（原计划 V2 再引入）~~ | **改为引入（本次修订）** | 仅做 **JWT 吊销黑名单**（登出即时失效），不承载会话/缓存；OAuth2 / 短信邮件验证码仍不做 |
| 前端 HTTPS 密码加密传输 | 由运维 HTTPS 保证 | V2 讨论 |

## 3. 技术选型

| 能力 | 选型 | 版本与放置 | 说明 |
|---|---|---|---|
| 认证与拦截框架 | **Spring Security** | `spring-boot-starter-security`（版本由 Boot 2.7.18 BOM 托管 = 5.7.11）→ `ocr-web` | **登录认证（`AuthenticationManager` + `DaoAuthenticationProvider` + `UserDetailsService`）与请求拦截（`SecurityFilterChain`）统一走 Spring Security**；Boot 2.7 用 `javax.*`，**禁止 `jakarta.*`** |
| 密码散列 | **BCrypt**（strength=10） | `spring-security-crypto`（随 starter 传递）→ `BCryptPasswordEncoder` Bean 放 `ocr-web` 供 `DaoAuthenticationProvider` 比对；`ocr-service` 保留 `PasswordSupport`（仅依赖 crypto 子包）做注册加密 | 自带随机盐；登录比对与注册加密同一算法同一强度 |
| 令牌 | **JWT（HS256）** | `jjwt-api / jjwt-impl / jjwt-jackson` **0.11.5**（JDK 8 兼容线）→ `ocr-service` | 0.12.x 起模块化与 JDK 要求变化，不冒险；claims 增加 `jti`（吊销粒度标识） |
| Token 吊销 | **Redis 黑名单（jti + TTL）** | `spring-boot-starter-data-redis`（Boot 2.7 BOM 托管，Lettuce 客户端）→ `ocr-service` | 登出把 jti 写入 `auth:blacklist:{jti}`，TTL = Token 剩余有效期，到期自动清理零积压；每次请求 `EXISTS` 校验；**Redis 读故障 fail-open**（可用性优先），详见 §7.3.1 |
| 请求鉴权 | **`JwtAuthenticationFilter` 挂入 Security 过滤器链** | `ocr-web` 的 `security` 包，`addFilterBefore(…, UsernamePasswordAuthenticationFilter.class)` | 不再用 `FilterRegistrationBean` 裸注册，统一由 `SecurityFilterChain` 编排 |
| 登录接口 | **自定义 `AuthController` + `AuthenticationManager`** | `ocr-web` | 保留 REST 风格 `POST /api/auth/login` 与统一 `LoginVO` 出参（不劫持表单 `UsernamePasswordAuthenticationFilter`，前端契约零改动）；Controller 内调 `authenticationManager.authenticate()` 完成认证 |
| 角色鉴权 | **`@PreAuthorize` + `@EnableGlobalMethodSecurity`** | 注解（`@PreAuthorize`）随 Spring Security；开关放 `ocr-web` 的 `SecurityConfig` | 替代原 `@RequireRoles` 自研切面；角色每次查库（不依赖 Redis，用户量小可接受） |
| 用户上下文 | **`SecurityContextHolder`** | Spring Security 内置（`DaoAuthenticationProvider` 写入 / `JwtAuthenticationFilter` 重建） | 替代自研 `ThreadLocal UserContext`；Spring Security 默认 `MODE_THREADLOCAL` + `SecurityContextPersistenceFilter` 负责清理，业务代码只读不写 |
| 异常输出 | **`AuthenticationEntryPoint` + `AccessDeniedHandler`** | `ocr-web` 的 `security` 包 | 401/403 统一走 Spring Security 回调，用全局 `ObjectMapper` 写出同构 `ApiResponse`（40100/40101/40102/40103/40300） |
| 树形结构 | **`parent_id` + `ancestors` 祖先链** | —— | 一次查全表内存组树，避免递归 SQL，为 V2 机构数据权限铺路 |
| 配置绑定 | `@ConfigurationProperties("security.jwt")` | `ocr-service` 的 `security` 包（与 `JwtTokenProvider` 同层；`@Component` + 注解即可被组件扫描，与 §5 一致） | 禁用 `@Value` 散落 |
| 敏感配置 | `${JWT_SECRET}` 环境变量占位 | `ocr-web/src/main/resources/application.yml` | 禁止明文密钥，与 `${DB_PASSWORD}` 一致 |

## 4. 数据模型设计

脚本：`backend/sql/02-auth-schema.sql`（四张表 + 初始化数据一次执行；DDL 统一放 `backend/sql/`；`01` 编号预留给 OCR 业务表脚本——当前 `sql/` 为空，本脚本是首个 DDL）。

### 4.1 表：`sys_user`（用户表 = 员工表）

```sql
CREATE TABLE sys_user (
    id            BIGINT       NOT NULL COMMENT '雪花 ID',
    org_id        BIGINT       DEFAULT NULL COMMENT '所属机构 ID（1:n 机构方持有），NULL=未分配',
    username      VARCHAR(32)  NOT NULL COMMENT '用户名，登录用',
    nickname      VARCHAR(64)  DEFAULT NULL COMMENT '昵称',
    email         VARCHAR(128) DEFAULT NULL COMMENT '邮箱',
    password_hash CHAR(60)     NOT NULL COMMENT 'BCrypt 密文，定长 60',
    status        TINYINT      NOT NULL DEFAULT 1 COMMENT '1=启用 0=禁用',
    failed_attempts INT        NOT NULL DEFAULT 0 COMMENT '连续登录失败次数',
    locked_until  DATETIME     DEFAULT NULL COMMENT '锁定到期时间',
    last_login_time DATETIME   DEFAULT NULL COMMENT '最近登录时间',
    last_login_ip VARCHAR(64)  DEFAULT NULL COMMENT '最近登录 IP',
    create_time   DATETIME     NOT NULL COMMENT '创建时间',
    update_time   DATETIME     NOT NULL COMMENT '更新时间',
    deleted       TINYINT      NOT NULL DEFAULT 0 COMMENT '逻辑删除 0=未删 1=已删',
    PRIMARY KEY (id),
    UNIQUE KEY uk_username (username),
    KEY idx_org_id (org_id),
    KEY idx_email (email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统用户表(员工)';
```

取舍：

- **`uk_username` 不含 `deleted`**：逻辑删除后用户名不可复用，防"注销后同名查到历史数据"；若要复用改 `uk_username_deleted (username, deleted)`。
- **`org_id` 不加物理外键**：全库不用 FK（逻辑删除与 FK 冲突），机构存在性由 Service 校验；`idx_org_id` 支撑"机构下员工列表"。
- **雪花 ID**：跟随全局 `id-type: assign_id`；`Long` 必须加 `@JsonSerialize(ToStringSerializer.class)`。
- **`email` 不唯一**：可空可共用，注册**不做邮箱查重**（`40021` 为预留错误码，本期不触发）；邮箱登录需求出现再升级。

### 4.2 表：`sys_org`（机构表，树形）

```sql
CREATE TABLE sys_org (
    id          BIGINT       NOT NULL COMMENT '雪花 ID',
    parent_id   BIGINT       NOT NULL DEFAULT 0 COMMENT '父机构 ID，0=根节点',
    ancestors   VARCHAR(512) NOT NULL DEFAULT '0' COMMENT '祖先链，逗号分隔，如 0,1001,1002',
    org_code    VARCHAR(32)  NOT NULL COMMENT '机构编码，业务唯一',
    org_name    VARCHAR(64)  NOT NULL COMMENT '机构名称',
    sort        INT          NOT NULL DEFAULT 0 COMMENT '同级排序，越小越靠前',
    status      TINYINT      NOT NULL DEFAULT 1 COMMENT '1=启用 0=停用',
    create_time DATETIME     NOT NULL COMMENT '创建时间',
    update_time DATETIME     NOT NULL COMMENT '更新时间',
    deleted     TINYINT      NOT NULL DEFAULT 0 COMMENT '逻辑删除 0=未删 1=已删',
    PRIMARY KEY (id),
    UNIQUE KEY uk_org_code (org_code),
    KEY idx_parent_id (parent_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='机构表(树形)';

-- 初始化：根机构与默认机构
INSERT INTO sys_org (id, parent_id, ancestors, org_code, org_name, sort, status, create_time, update_time, deleted)
VALUES (1, 0, '0', 'ROOT', '根机构', 0, 1, NOW(), NOW(), 0),
       (2, 1, '0,1', 'DEFAULT', '默认机构', 0, 1, NOW(), NOW(), 0);
```

取舍：

- **`ancestors` 祖先链**：子树查询（"本机构及以下"）用 `like '0,1001%'` 即可，**无需递归 SQL**、不依赖 MySQL 8 CTE；代价是移动子树需级联重写后代 `ancestors`（§7.6）。
- **量级假设**：机构数 < 数千，**查全表内存组树**返回，不分页；量级暴涨再改 `?parent_id=` 懒加载。
- **初始化数据**：内置 `ROOT`（根）与 `DEFAULT`（默认）；注册未指定机构时挂 `DEFAULT`。
- **删除保护**：仍有子机构或在职员工（`sys_user.org_id` 引用且未删）时禁止删除，返回 `ORG_HAS_CHILDREN` / `ORG_HAS_USERS`。

### 4.3 表：`sys_role`（角色表）

```sql
CREATE TABLE sys_role (
    id          BIGINT       NOT NULL COMMENT '雪花 ID',
    role_code   VARCHAR(64)  NOT NULL COMMENT '角色编码，程序鉴权用，如 ADMIN / USER',
    role_name   VARCHAR(64)  NOT NULL COMMENT '角色名称，展示用',
    description VARCHAR(255) DEFAULT NULL COMMENT '角色描述',
    status      TINYINT      NOT NULL DEFAULT 1 COMMENT '1=启用 0=停用',
    built_in    TINYINT      NOT NULL DEFAULT 0 COMMENT '1=内置角色禁止修改删除',
    create_time DATETIME     NOT NULL COMMENT '创建时间',
    update_time DATETIME     NOT NULL COMMENT '更新时间',
    deleted     TINYINT      NOT NULL DEFAULT 0 COMMENT '逻辑删除 0=未删 1=已删',
    PRIMARY KEY (id),
    UNIQUE KEY uk_role_code (role_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色表';

-- 初始化：内置角色
INSERT INTO sys_role (id, role_code, role_name, description, status, built_in, create_time, update_time, deleted)
VALUES (1, 'ADMIN', '系统管理员', '管理机构/角色/用户分配', 1, 1, NOW(), NOW(), 0),
       (2, 'USER',  '普通用户',   '注册默认角色',           1, 1, NOW(), NOW(), 0);
```

取舍：

- **`role_code` 唯一且不可变**：鉴权逻辑绑定编码而非 id/名称；`role_name` 可随意改。
- **内置角色保护**：`built_in=1` 的 `ADMIN`/`USER` 禁止编辑/删除（错误码 `ROLE_BUILT_IN`），防止把自己锁在门外。
- **注册默认角色**：注册成功自动绑定 `USER`，保证 `/me` 永远有角色返回、鉴权语义完整。

### 4.4 表：`sys_user_role`（角色用户关联表，n:m）

```sql
CREATE TABLE sys_user_role (
    id          BIGINT   NOT NULL COMMENT '雪花 ID',
    user_id     BIGINT   NOT NULL COMMENT '用户 ID',
    role_id     BIGINT   NOT NULL COMMENT '角色 ID',
    create_time DATETIME NOT NULL COMMENT '绑定时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_user_role (user_id, role_id),
    KEY idx_role_id (role_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户角色关联表(n:m)';
```

取舍：

- **物理删除、不建 `deleted` 字段**：全局 `logic-delete-field: deleted` 只对含该字段的实体生效，无该字段即物理删除；若逻辑删除，"解绑再绑"会撞 `uk_user_role` 唯一索引。
- **无 `update_time`**：绑定只有"建立/解除"语义；重新分配走"事务内 delete + batch insert"全量替换（§9.4），靠 `uk_user_role` 兜底防重复。
- **n:m 查询**：`me`/登录的角色列表 = 按 `user_id` 查关联 + 按 `role_id` 集合查角色，两次单表查询内存组装（遵循"多表 join 才写 XML"约定）。

### 4.5 ER 总览与扩展位

```
sys_org (机构树) 1 ──< n sys_user (用户=员工, org_id)
sys_user m ──< sys_user_role (uk_user_role) >── n sys_role (built_in 保护)
```

V2 扩展位（不建表不阻塞）：`sys_menu` + `sys_role_menu`（菜单/按钮权限）、`sys_refresh_token`（刷新令牌持久化）、机构数据权限。

## 6. 错误码设计

`ResultCode` 追加（沿用分段：0 成功 / 4xxxx 客户端 / 5xxxx 系统 / 503xx OCR）：

| 枚举 | code | message | 触发场景 |
|---|---|---|---|
| `UNAUTHORIZED` | 40100 | 未登录或令牌缺失 | Header 无 `Authorization` |
| `TOKEN_INVALID` | 40101 | 令牌无效 | 签名不符 / 被篡改 |
| `TOKEN_EXPIRED` | 40102 | 令牌已过期 | JWT 过期 |
| `TOKEN_REVOKED` | 40103 | 登录已失效，请重新登录 | 已登出吊销的 Token 再访问（Redis 黑名单命中，`RestAuthEntryPoint` 输出） |
| `FORBIDDEN` | 40300 | 无权限访问 | `@PreAuthorize` 校验不通过（`RestAccessDeniedHandler` 输出） |
| `USERNAME_EXISTS` | 40020 | 用户名已存在 | 注册重名 |
| `EMAIL_EXISTS` | 40021 | 预留（本期不触发） | `email` 非唯一（§4.1），注册不校验邮箱重复；V2 启用邮箱唯一/邮箱登录时生效 |
| `PASSWORD_ERROR` | 40022 | 用户名或密码错误 | **统一提示，不区分用户是否存在（防账号枚举）** |
| `USER_DISABLED` | 40023 | 账号已被禁用 | `status = 0` |
| `ACCOUNT_LOCKED` | 40024 | 登录失败次数过多，请 15 分钟后再试 | 失败锁定中 |
| `REFRESH_TOKEN_INVALID` | 40025 | 刷新令牌无效 | refresh 接口 |
| `ORG_NOT_FOUND` | 40026 | 机构不存在 | 传入 orgId 查无/已删 |
| `ORG_HAS_CHILDREN` | 40027 | 存在下级机构，禁止删除 | 机构删除校验 |
| `ORG_HAS_USERS` | 40028 | 机构下存在员工，禁止删除 | 机构删除校验 |
| `ROLE_CODE_EXISTS` | 40029 | 角色编码已存在 | 角色新增/改码 |
| `ROLE_IN_USE` | 40030 | 角色已分配用户，禁止删除 | 角色删除校验 |
| `ROLE_BUILT_IN` | 40031 | 内置角色禁止此操作 | 编辑/删除 ADMIN/USER |
| `USER_NOT_FOUND` | 40032 | 用户不存在 | 管理端操作的目标用户查无/已删 |
| `ORG_CODE_EXISTS` | 40033 | 机构编码已存在 | 机构新增撞 `uk_org_code` |
| `ROLE_NOT_FOUND` | 40034 | 角色不存在或已停用 | 管理端/分配角色时查无 |

**HTTP 状态码策略**：业务响应一律 HTTP 200 + `code` 非零；鉴权类响应 **HTTP 401**（未认证/令牌异常，code ∈ 40100/40101/40102/40103/40023）、**HTTP 403**（无权限，code 40300），JSON 体与 `ApiResponse` 同构。401 有**两条通路**：① **链尾回调**——请求无 Token/未认证，由链尾 `FilterSecurityInterceptor` 触发 `RestAuthEntryPoint`（40100）；② **Filter 手动接管**——Token 过期/篡改/`type≠access`/黑名单命中/用户禁用均发生在 `JwtAuthenticationFilter` 内部，而 `ExceptionTranslationFilter` 位于该 Filter **之后**，此处抛出的 `AuthenticationException` 传播不到 `RestAuthEntryPoint`，**必须 Filter 内 try-catch 后手动调用 `restAuthEntryPoint.commence()` 写出**（40101/40102/40103/40023，见 §10）。两条通路**必须用全局 `ObjectMapper` 序列化**（保证时间格式一致），禁止手写拼接 JSON。403 有**两条独立通路**必须分别处理：URL 级授权拒绝（`ExceptionTranslationFilter` 阶段）由 `RestAccessDeniedHandler` 输出；**方法级 `@PreAuthorize` 拒绝抛出的 `AccessDeniedException` 发生在 MVC 层，会先被 `GlobalExceptionHandler` 的 `Exception` 兜底 Handler 截获（吃成 500、绕过 `RestAccessDeniedHandler`），必须在 `GlobalExceptionHandler` 显式新增 `AccessDeniedException` Handler 输出 `40300`**（见 §10.1 第 5 项）。`BadCredentialsException` / `DisabledException` / `LockedException` 由 `AuthController` 捕获翻译为 `40022` / `40023` / `40024`。`GlobalExceptionHandler` 共新增三个 Handler：`AccessDeniedException`（→ 40300）、`DuplicateKeyException`（并发撞唯一索引，按约束名映射 `uk_username→40020` / `uk_role_code→40029` / `uk_org_code→40033`，无法识别归 `SYSTEM_ERROR`）、`AuthenticationException`（漏网归一 → 40100）；`MethodArgumentNotValidException` 已有，各 DTO 直接受益。

### 7.2 `ocr-web`：`UserDetailsServiceImpl`（Spring Security 认证模型）

自研 `UserContext` / `@RequireRoles` **取消**，由 Spring Security 标准模型替代：

```java
@Service
public class UserDetailsServiceImpl implements UserDetailsService {

    @Override
    public UserDetails loadUserByUsername(String username) {
        // 1. LambdaQueryWrapper 按 username 查 UserDO（eq 自动带 deleted=0）
        // 2. 查角色编码集合 → List<SimpleGrantedAuthority>（ROLE_ 前缀：ROLE_ADMIN / ROLE_USER）
        // 3. 映射 Spring Security 内置 User：
        //    - status == 0                → new User(..., false, ...)   → 认证抛 DisabledException → 40023
        //    - lockedUntil 未到期          → new User(..., accLocked)    → 认证抛 LockedException   → 40024
        //    - 密码用 UserDO.passwordHash（BCrypt 比对由 DaoAuthenticationProvider 完成）
        // 4. 自定义 principal 携带 userId（继承 User 扩展字段），供 JWT 签发与 @PreAuthorize 之外的读取
        // 用户不存在 → UsernameNotFoundException（DaoAuthenticationProvider 默认掩码为 BadCredentials → 40022，防账号枚举）
    }
}
```

- **角色即权限**：`ROLE_` 前缀是 Spring Security 约定，`hasRole('ADMIN')` 自动匹配 `ROLE_ADMIN`；角色每次查库、不缓存（与原设计一致）。
- **取当前用户**：业务代码统一 `SecurityContextHolder.getContext().getAuthentication()`，不再自维护 ThreadLocal；Spring Security 过滤器链负责请求级清理，无线程池串号风险。
- **跨模块红线**：`UserDetails` / `SecurityContextHolder` / `SecurityFilterChain` 等 Spring Security **web/config 类只允许出现在 `ocr-web`**；`ocr-service` 仅允许 `spring-security-crypto`（`PasswordSupport`）；`ocr-common` **零依赖**（Service 层需要 userId 时由 Controller 从 Authentication 取出后作为方法参数传入）。

### 7.3 `ocr-service`：`JwtTokenProvider` 与 `AuthProperties`

```java
@Component
public class JwtTokenProvider {
    // Claims: sub=userId(String), username, type(access/refresh), jti=UUID, iat, exp
    // 禁止把密码/邮箱放 payload（JWT 仅 Base64Url 编码）
    public String generateAccessToken(Long userId, String username) { ... }  // JJWT .setId(UUID) 写入 jti
    public String generateRefreshToken(Long userId) { ... }
    public Claims parse(String token) { ... }   // 过期/签名异常抛 BusinessException(TOKEN_EXPIRED / TOKEN_INVALID)——不做内部消化，输出通路由调用方决定（Filter 包成 AuthFailureException 经 EntryPoint 写出；refresh 接口转 40025）
}
```

> **角色不放 JWT**：角色变更（如被提权/撤权）需即时生效，角色每次查库；用户量小无性能问题，引入缓存留 V2。
> **`jti` 必须有**：每个 Token 签发时生成 UUID 作为唯一标识（JJWT `.setId()`），是黑名单的吊销粒度单位——吊销的是"这一个 Token"，而非全端下线。
>
> **`type` 必须校验（两处都做）**：`JwtAuthenticationFilter` 只认 `type=access`（refreshToken 直接当 accessToken 调接口 → 40101，堵死 7d 长效 Token 绕过 accessToken ≤2h 短有效期这一安全兜底）；`/api/auth/refresh` 只认 `type=refresh`（accessToken 传入 → 40025）。

### 7.3.1 `ocr-service`：`TokenBlacklistService`（Redis 吊销黑名单）

```java
@Component
public class TokenBlacklistService {
    private final StringRedisTemplate redis;   // String 序列化足够，无需 JSON 模板

    /** 吊销：SET auth:blacklist:{jti} 1 EX 剩余秒数（到期自动清理，零维护零积压） */
    public void revoke(String jti, long ttlSeconds) { ... }

    /** 校验：EXISTS auth:blacklist:{jti}；Redis 异常一律返回 false（fail-open 放行） */
    public boolean isRevoked(String jti) { ... }
}
```

| 设计点 | 约定 |
|---|---|
| Key 设计 | `auth:blacklist:{jti}`，value 固定 `1`（只需存在性语义） |
| TTL | = Token 剩余有效期（`exp - now`）：Token 自然过期后黑名单条目同步消失，不积压、无需清理任务 |
| 写入时机 | **仅登出**：吊销 accessToken 与 refreshToken 双 jti（未传 refreshToken 则只吊销 accessToken）；refresh 不轮换、不写黑名单 |
| 读故障降级 | **fail-open**：查询异常（拒绝连接/超时）记 WARN 后视为"未吊销"放行——保可用性；降级窗口内吊销暂失效，由 accessToken ≤2h 短有效期兜底 |
| 写故障降级 | 登出时写入失败 → 返回 `SYSTEM_ERROR`（50000）用户可重试，**不静默成功**（吊销失败却提示登出成功是安全语义漏洞） |
| command timeout | yml 显式 `timeout: 1000ms`——Lettuce 默认 60s 会拖死请求线程，fail-open 前提是快速失败 |
| 不承载会话 | Redis 仅作 KV 存储，`SessionCreationPolicy.STATELESS` 不变，不引入 Spring Session |
| 依赖位置 | `spring-boot-starter-data-redis`（Boot 2.7 BOM 托管，前缀 `spring.redis.*`）声明在 `ocr-service`——与 `TokenBlacklistService` 同层；`ocr-web` 经传递依赖使用 |

`AuthProperties`（`@ConfigurationProperties(prefix = "security.jwt")`）：`secret` / `accessTokenTtl=7200` / `refreshTokenTtl=604800` / `maxFailedAttempts=5` / `lockDurationMinutes=15` / `enabled=true`（一键降级开关）。

### 7.4 `ocr-web`：方法级鉴权（替代原 `RequireRolesAspect`）

自研切面取消，改用 Spring Security 方法级安全：

```java
// SecurityConfig 开启（Boot 2.7 / Security 5.7 写法）
@EnableGlobalMethodSecurity(prePostEnabled = true)   // 启用 @PreAuthorize

// Controller 用法（等价于原 @RequireRoles("ADMIN")，满足任一角色即通过）
@PostMapping("/api/roles")
public ApiResponse<String> create(@RequestBody @Validated RoleSaveDTO dto) { ... }

// 多角色任一满足：@PreAuthorize("hasAnyRole('ADMIN','AUDITOR')")
```

- **拒绝语义**：未登录调用 → `RestAuthEntryPoint`（40100）；已登录但角色不足 → `RestAccessDeniedHandler`（40300），错误码与原设计完全一致。
- **异常翻译**：`AuthController` 捕获 `AuthenticationException` 子类映射：`BadCredentialsException` → 40022、`DisabledException` → 40023、`LockedException` → 40024、`UsernameNotFoundException`（被 Provider 掩码）→ 40022。
- **失败计数**：锁定/计数逻辑不进 `DaoAuthenticationProvider`（保持 Provider 纯净），由 `AuthController` 在认证结果后按"成功清零 / 失败 +1（达阈值写 lockedUntil）"短事务处理（§7.5）。

### 7.5 `ocr-web`：`AuthController#login`（经 `AuthenticationManager` 认证）与注册流程

登录（**认证全部走 Spring Security，编排层只做异常翻译与令牌签发**）：

```
1. 参数已由 @Validated 校验通过（username 4~32 / password 8~20）
2. authenticationManager.authenticate(new UsernamePasswordAuthenticationToken(username, password))
   ├─ UserDetailsServiceImpl 按 username 查 UserDO（eq 自动带 deleted=0），角色编码 → ROLE_xxx authorities
   ├─ 用户不存在 → UsernameNotFoundException → DaoAuthenticationProvider 掩码为 BadCredentialsException（防枚举）
   ├─ BCrypt 密码比对由 DaoAuthenticationProvider + BCryptPasswordEncoder 完成（不再手写 matches）
   ├─ status == 0 → DisabledException；lockedUntil 未到期 → LockedException
   └─ Controller 捕获翻译：BadCredentials → 40022 / Disabled → 40023 / Locked → 40024
3. 认证失败：**SQL 原子自增**（`UPDATE sys_user SET failed_attempts = failed_attempts + 1, locked_until = IF(failed_attempts + 1 >= 阈值, NOW() + INTERVAL 锁定分钟 MINUTE, locked_until) WHERE id = ?`；**禁止"先查后写"的 read-modify-write**——并发请求会丢失更新、绕过 5 次阈值）→ 抛 BusinessException(PASSWORD_ERROR)
4. 认证成功：单条 UPDATE 清零（`failed_attempts = 0, locked_until = NULL`），写 lastLoginTime / lastLoginIp（IP 由 Controller 从 HttpServletRequest 取）
5. 从 Authentication.principal 取 userId/username → 查机构名 + 角色编码集合
6. JwtTokenProvider 签发 accessToken / refreshToken → 组装 LoginVO
```

注册（`@Transactional(rollbackFor = Exception.class)`）：

```
1. 用户名唯一性校验（并发兜底靠 DuplicateKeyException → USERNAME_EXISTS）
2. orgId 为空 → 取 DEFAULT 机构；非空 → 校验存在且启用（否则 ORG_NOT_FOUND）
3. BCrypt 加密落库 sys_user（审计字段自动填充）
4. 绑定默认角色 USER（sys_user_role insert）
```

**事务红线**：`@Transactional(rollbackFor = Exception.class)` 只加在 ServiceImpl；**事务内禁止 HTTP 调用**（OCR 推理可达 10 分钟）；失败计数/登录成功各自短事务，不包 BCrypt 校验于同一大事务。

## 8. 安全设计要点

| 主题 | 设计 |
|---|---|
| 密码强度 | 8~20 位；规则统一收口 `RegisterDTO` 注解 + `PasswordSupport`，单点修改 |
| 密码存储 | BCrypt(strength=10)；**禁止 MD5 / SHA / 明文**；日志严禁打印密码原文 |
| 账号枚举防护 | 用户不存在与密码错误返回**同一错误码 40022、同一文案** |
| 暴力破解 | 连续失败 5 次锁 15 分钟（DB 计数，跨实例共享）；成功登录清零 |
| 平行越权 | "我的资源"查询强制 `userId` 取自 `SecurityContextHolder`（Controller 层取出传入 Service），**禁止信任前端传 userId**；管理接口（机构/角色/用户管理）已全部 `@PreAuthorize`（§7.4），非 ADMIN 一律 40300 |
| 垂直越权 | 机构/角色/用户分配接口全部 `ADMIN`；内置角色防删（`ROLE_BUILT_IN`）防自锁；403 双通路输出 40300（URL 级 `RestAccessDeniedHandler` / 方法级 `GlobalExceptionHandler`，§10.1 第 5 项） |
| 角色即时性 | 角色不放 JWT、每次查库（`UserDetailsServiceImpl` / `JwtAuthenticationFilter` 重建 authorities）→ 撤权即时生效；Token 只认 userId |
| Token 即时吊销 | `JwtAuthenticationFilter` 验签通过后查 `TokenBlacklistService`（jti 命中 → `AuthFailureException(40103)` 手动经 `restAuthEntryPoint.commence()` 输出，见 §10）；Redis 读故障 fail-open 放行 + WARN 日志；`security.jwt.enabled=false` 软鉴权时黑名单校验一并跳过（§10） |
| Token 传输 | `Authorization: Bearer <token>`；`CorsConfig` 为 `WebMvcConfigurer#addCorsMappings` 实现（MVC 层生效，工程内**无** `CorsConfigurationSource` Bean），Security 侧**不启用 `http.cors()`**——预检靠 `antMatchers(OPTIONS).permitAll()` 穿过过滤器链后，交 MVC 层 `CorsConfig` 应答（`maxAge=3600` 已降低预检频率）；生产 Nginx 同域 + HTTPS |
| Token 登出 | **Redis 黑名单即时吊销**：`/logout` 从 Header 取 accessToken、Body（可选）取 refreshToken，双双按 `jti` 写入黑名单（TTL=各自剩余有效期）→ 旧 Token 立即失效（accessToken → 40103 / refreshToken → 40025）；前端同时删本地 token；Redis 写失败 → 登出返回 50000 可重试 |
| 令牌刷新 | accessToken 2h + refreshToken 7d；access 过期返回 40102，前端静默 `/refresh` 换新；refresh 前先查黑名单（已登出吊销的 refreshToken → 40025，堵死"登出后用 refreshToken 复活"路径）；本期不轮换（轮换留 V2） |
| 配置安全 | `security.jwt.secret` 走 `${JWT_SECRET}`（HS256 ≥ 32 字符）；prod 缺失启动失败 |
| SQL 注入 | 全部 `LambdaQueryWrapper`；**禁止 `apply`/`last` 拼接用户输入** |
| CSRF | 纯 Header Bearer Token（无 Cookie 会话），`http.csrf().disable()`；若 V2 切 Cookie 承载再开启 |
| 会话 | `SESSIONLESS`：`SessionCreationPolicy.STATELESS`（禁 HttpSession，防 SESSID 泄漏与串号） |
| 依赖红线 | 全部 `javax.*`；JJWT 0.11.5 与 JDK 8 匹配；Spring Security 版本锁 5.7.x（Boot 2.7 BOM），禁止升级 6.x（jakarta） |

## 9. API 设计（全接口出入参）

统一前缀 `/api`，返回 `ApiResponse<T>`（`code / message / data / timestamp`），**下文"响应"仅描述 `data` 部分**。通用约定：

- 所有 `Long` 类型的 id 在 JSON 中**一律为字符串**（`ToStringSerializer`）；
- 时间字段格式 `yyyy-MM-dd HH:mm:ss`（GMT+8）；
- 参数校验失败统一返回现有 `40000`（`MethodArgumentNotValidException`）；
- 鉴权接口需带 Header：`Authorization: Bearer <accessToken>`，缺失/无效/已吊销返回 `40100 / 40101 / 40102 / 40103`，下文不再重复。

#### 9.1.2 登录 `POST /api/auth/login`（匿名）

请求 Body（`LoginDTO`）：

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| username | string | 是 | 4~32 位 |

| 字段 | 类型 | 说明 |
|---|---|---|
| accessToken | string | 访问令牌，默认 2h |
| refreshToken | string | 刷新令牌，默认 7d |
| tokenType | string | 固定 `Bearer` |
| expiresIn | number | accessToken 有效秒数，取 `security.jwt.access-token-ttl` 配置值（默认 7200） |
| user | UserInfoVO | 同 9.1.1 出参 |

#### 9.1.3 刷新令牌 `POST /api/auth/refresh`（匿名）

请求 Body（`RefreshTokenDTO`）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| refreshToken | string | 是 | 登录时下发的刷新令牌 |

响应 `data`（`TokenVO`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| accessToken | string | 新访问令牌 |
| tokenType | string | `Bearer` |
| expiresIn | number | 取 `security.jwt.access-token-ttl` 配置值（默认 7200） |

> 服务端先校验 `claims.type == refresh`（accessToken 传入 → `40025`，防访问令牌当刷新令牌用），再查 Redis 黑名单：已登出吊销的 refreshToken 直接 `40025`（堵死"登出后复活"）。V1 不轮换 refreshToken（未登出时旧 refreshToken 到期前可重复换新 accessToken，轮换留 V2）。

失败：`40025` 刷新令牌无效/过期/已吊销。

#### 9.1.4 当前用户 `GET /api/auth/me`（鉴权）

请求：无 Body、无 Query，仅需鉴权 Header。

响应 `data`：`UserInfoVO`，结构同 9.1.1 出参（实时查库，角色/机构/禁用状态即时生效）。

失败：`40100/40101/40102`（HTTP 401）；用户已被禁用时返回 `40023`（HTTP 401）。

#### 9.1.5 登出 `POST /api/auth/logout`（鉴权）

请求：鉴权 Header 携带 accessToken；Body（`LogoutDTO`，可选）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| refreshToken | string | 否 | 传入则一并吊销；不传只吊销当前 accessToken |

服务端动作：解析 accessToken / refreshToken 的 `jti` 与剩余有效期 → 双双写入 Redis 黑名单（TTL = 各自剩余有效期）→ 旧 Token **立即失效**。前端登出成功后同时删除本地两个 token。

响应：`data` 为 `null`（`{ "code": 0, "message": "成功", "data": null, "timestamp": ... }`）。

失败：`40100/40101/40102`（accessToken 无效）；`50000`（Redis 写黑名单失败，可重试登出，不静默成功）。

鉴权失败示例（`RestAuthEntryPoint` / `RestAccessDeniedHandler` 写出，同构 `ApiResponse`）：

```json
{ "code": 40103, "message": "登录已失效，请重新登录", "data": null, "timestamp": 1780000000000 }
```

前端 axios 拦截器约定（鉴权类响应 HTTP 401/403 走 axios 错误分支，从 `error.response.data.code` 取码）：`code` ∈ {40100, 40101, 40102, 40103} → 清 token 跳登录页；`40023` → 清 token 跳登录页并提示"账号已被禁用"；`40300` → 提示无权限。

## 10. 配置项（`ocr-web/src/main/resources/application.yml` 追加）

```yaml
# application.yml 既有 spring 块内追加（Boot 2.7 前缀是 spring.redis.*，3.x 才是 spring.data.redis）
spring:
  redis:
    host: ${REDIS_HOST:localhost}
    port: ${REDIS_PORT:6379}
    password: ${REDIS_PASSWORD:}
    timeout: 1000ms        # command 超时必须调短（Lettuce 默认 60s 会拖死请求线程），fail-open 的前提

security:
  jwt:
    secret: ${JWT_SECRET}        # 禁止明文；HS256 要求 ≥ 32 字符
    access-token-ttl: 7200
    refresh-token-ttl: 604800
    max-failed-attempts: 5
    lock-duration-minutes: 15
    enabled: true                # 故障一键关闭鉴权（降级开关，生产慎用）
```

父 POM 追加：`<jjwt.version>0.11.5</jjwt.version>` 进 `<properties>` + `dependencyManagement` 收口 jjwt 三件套；`spring-boot-starter-security` 由 Boot 2.7 BOM 托管（5.7.11），**声明在 `ocr-web`**，无需版本号；`spring-boot-starter-data-redis`（Lettuce）同样由 BOM 托管，**声明在 `ocr-service`**（`TokenBlacklistService` 所在层，经传递依赖供 `ocr-web` 使用）；另：**`spring-security-crypto` 由 BOM 托管、显式声明在 `ocr-service`**（`PasswordSupport` 编译所需——ocr-service 不依赖 security starter，不显式声明则编译失败）；原 `spring-boot-starter-aop` 收口取消（`@PreAuthorize` 由 security 的 AOP 机制承载）。

`SecurityConfig`（Boot 2.7 / Security 5.7 推荐 `SecurityFilterChain` Bean 写法，`WebSecurityConfigurerAdapter` 已废弃不再使用）：

```java
@Configuration
@EnableGlobalMethodSecurity(prePostEnabled = true)   // 启用 @PreAuthorize
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http.csrf().disable()                                    // 纯 Bearer，无 Cookie
            .sessionManagement().sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            .and()
            .authorizeRequests()
            .antMatchers(HttpMethod.OPTIONS).permitAll()          // 预检放行（CorsConfig 依赖）
            .antMatchers(                                        // 白名单
                "/api/auth/register",
                "/api/auth/login",
                "/api/auth/refresh",
                "/api/health").permitAll()
            .antMatchers("/api/**").authenticated()              // 其余 /api/** 需认证
            .anyRequest().permitAll()                            // /druid、/swagger-ui 等非 /api 不在链上管
            .and()
            .exceptionHandling()
            .authenticationEntryPoint(restAuthEntryPoint)         // 401 → 40100/40101/40102 JSON
            .accessDeniedHandler(restAccessDeniedHandler)         // 403 → 40300 JSON
            .and()
            .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    @Bean
    public AuthenticationManager authenticationManager(AuthenticationConfiguration cfg) throws Exception {
        return cfg.getAuthenticationManager();                   // 供 AuthController 登录使用
    }

    @Bean
    public DaoAuthenticationProvider daoAuthenticationProvider(UserDetailsServiceImpl uds, BCryptPasswordEncoder encoder) {
        DaoAuthenticationProvider provider = new DaoAuthenticationProvider();
        provider.setUserDetailsService(uds);
        provider.setPasswordEncoder(encoder);                    // BCrypt(strength=10)
        return provider;
    }

    @Bean
    public BCryptPasswordEncoder passwordEncoder() { return new BCryptPasswordEncoder(10); }
}
```

`JwtAuthenticationFilter`（`OncePerRequestFilter`）逻辑——**核心纠偏：本 Filter 挂在 `UsernamePasswordAuthenticationFilter` 之前，`ExceptionTranslationFilter` 在其后，Filter 内抛出的 `AuthenticationException` 传播不到 `RestAuthEntryPoint`（会穿透成 500），所有 Token 异常必须由 Filter 自行 try-catch 并手动调用 `restAuthEntryPoint.commence()` 输出**：

1. 无 `Authorization` 头或非 Bearer 格式 → **不写响应、不放认证**，直接 `chain.doFilter`，由链尾 `FilterSecurityInterceptor` 触发 `RestAuthEntryPoint`（40100）；
2. `JwtTokenProvider.parse` 抛 `BusinessException`（40102 过期 / 40101 签名不符或篡改）→ 捕获后包成 `AuthFailureException(对应 ResultCode)`；
3. 校验 `claims.type == access`（refreshToken 当 accessToken 用 → `AuthFailureException(40101)`）；
4. **查黑名单**：`TokenBlacklistService#isRevoked(claims.getId())` 命中 → `AuthFailureException(40103)`；Redis 读故障 **fail-open 放行**（记 WARN）；
5. `UserDetailsServiceImpl` 装载用户+角色，检查 `UserDetails.isEnabled()`（禁用 → `AuthFailureException(40023)`）；
6. 步骤 2~5 任一失败 → **try-catch 内手动调用 `restAuthEntryPoint.commence(request, response, authFailureException)` 写响应后 `return`**（不再 `chain.doFilter`）；
7. 全部通过 → `UsernamePasswordAuthenticationToken` 写入 `SecurityContextHolder` → `chain.doFilter` 放行。

`AuthFailureException extends AuthenticationException`（`ocr-web` security 包）携带 `ResultCode`；`RestAuthEntryPoint#commence` 优先读取其携带的 code、缺省输出 40100，HTTP 状态码统一 401。**不手工管理 ThreadLocal，不手写 JSON**（全部经 `EntryPoint`/`Handler` + 全局 `ObjectMapper`）；上下文清理由 Spring Security 的 `SecurityContextPersistenceFilter`（STATELESS 下请求结束自动清空）完成。OPTIONS 预检由链上 `permitAll` 放行，`CorsConfig` 不受影响。

> **`security.jwt.enabled=false` 降级开关语义**：应急开关——关闭时把 `/api/**` 全量加入 `permitAll`（`JwtAuthenticationFilter` 照常解析 Token 仅填充上下文，**黑名单校验一并跳过**），实现"软鉴权"，生产慎用。

### 10.1 与既有配置的冲突核对清单（已逐项核实代码现状）

引入 `spring-boot-starter-security` 对存量功能的影响与处理：

| # | 冲突点 | 现状（已核实） | 处理 |
|---|---|---|---|
| 1 | Boot 默认行为：全请求 302 登录页 + 控制台随机密码 | 引入 starter 即生效 | 自定义 `SecurityFilterChain` 覆盖默认链；存在自定义 `UserDetailsService` Bean 后 `UserDetailsServiceAutoConfiguration` 退避，不再生成默认 user |
| 2 | Druid 监控台 `/druid/**` 被拦截 | yml `stat-view-servlet.enabled=true`，自带 `login-username/password` 独立认证 | `anyRequest().permitAll()`（链只管 `/api/**`），Druid 自身账密认证继续接管；生产仍建议 Nginx 屏蔽外网访问 |
| 3 | springdoc `/swagger-ui/**`、`/v3/api-docs/**` 被拦截 | `springdoc-openapi-ui` 1.x | 同上 `anyRequest().permitAll()` 放行；`OpenApiConfig` 配 Bearer 安全校验后可直接调试鉴权接口 |
| 4 | 跨域预检 OPTIONS 被 401（预检不带 Authorization） | `CorsConfig` 为 MVC 层 `addCorsMappings` 实现，无 `CorsConfigurationSource` Bean | `.antMatchers(HttpMethod.OPTIONS).permitAll()` 放行预检 → 到达 MVC 层由 `CorsConfig` 应答；Security 侧不启用 `http.cors()`，两套 CORS 配置不叠加 |
| 5 | **方法级 `@PreAuthorize` 拒绝返回 500** | `GlobalExceptionHandler#handleOther`（`Exception` 兜底）会先截获 `AccessDeniedException`，异常到不了 `RestAccessDeniedHandler` | **必须**新增 `@ExceptionHandler(AccessDeniedException.class)` → `ApiResponse.fail(ResultCode.FORBIDDEN)`（40300）。`@PreAuthorize` 是 AOP 层异常，走 `HandlerExceptionResolver`（`@RestControllerAdvice`）；与 Filter 链阶段 `ExceptionTranslationFilter` → `AccessDeniedHandler` 是两条不同通路 |
| 6 | Druid StatViewServlet 依赖 Session | `SessionCreationPolicy.STATELESS` 仅约束 Spring Security 不创建/不读取 HttpSession，不禁止其他组件使用 | 无冲突：Druid 自行 `getSession()` 不受影响，业务接口链路保持 STATELESS |
| 7 | 401/403 默认响应为 HTML/空体，破坏 `ApiResponse` 契约 | Security 默认 `EntryPoint`/`DeniedHandler` 非 JSON | `RestAuthEntryPoint` / `RestAccessDeniedHandler` 注入全局 `ObjectMapper` 写出同构 `ApiResponse` |
| 8 | 版本漂移引入 jakarta 断代 | Boot 2.7.18 BOM 托管 Security 5.7.11 | `ocr-web` 声明 starter **不写版本号**；锁 5.7.x，禁升 6.x |
| 9 | 引入 Redis 是否破坏 STATELESS | Redis 仅作 KV（黑名单存在性），非会话存储 | `SessionCreationPolicy.STATELESS` 不变；不引入 Spring Session；Boot 2.7 配置前缀为 `spring.redis.*`（勿照抄 3.x 的 `spring.data.redis.*`） |
| 10 | **自定义 Filter 内抛 `AuthenticationException` 到不了 `ExceptionTranslationFilter`** | `JwtAuthenticationFilter` 挂在 `UsernamePasswordAuthenticationFilter` 之前，`ExceptionTranslationFilter` 在其后 | Filter 内 try-catch，手动调用 `restAuthEntryPoint.commence()` 写响应后 `return`（§10 Filter 逻辑第 6 步）；`RestAuthEntryPoint` 识别 `AuthFailureException` 携带的 code（40101/40102/40103/40023） |

> 第 5 项是最易踩的坑：光配 `RestAccessDeniedHandler` 只覆盖 URL 级拒绝；`@PreAuthorize` 的 `AccessDeniedException` 必须由 `GlobalExceptionHandler` 接住，否则被兜底 Handler 吃成 `500 SYSTEM_ERROR`。

## 13. 风险与取舍

| 风险 | 影响 | 应对 |
|---|---|---|
| Spring Security 过滤器链与既有配置冲突 | 默认链拦截 `/druid`、`/swagger-ui`；401/403 默认响应非 `ApiResponse`；`@PreAuthorize` 拒绝被 `GlobalExceptionHandler` 兜底吃成 500 | §10.1 冲突核对清单八项逐一处理：`anyRequest().permitAll()` 只管 `/api/**`；401/403 统一 `RestAuthEntryPoint`/`RestAccessDeniedHandler` 输出 JSON；**`GlobalExceptionHandler` 新增 `AccessDeniedException` Handler（40300）**；版本锁 5.7.x（Boot 2.7 BOM），禁止 6.x |
| Spring Security 类扩散到业务模块 | 分层污染（`ocr-common`/`ocr-service` 依赖 security） | §7.2 跨模块红线：web/config 类仅限 `ocr-web`；`ocr-service` 仅 crypto；Controller 取 userId 传参给 Service |
| 角色每次查库 | 高频请求多两次 SQL | 用户量小可接受；V2 本地缓存（角色变更时失效） |
| 机构树移动子树需级联重写 ancestors | 数据一致性 | 本期禁改 `parent_id`，移动接口延后到 V2 专项 |
| 逻辑删除与唯一索引冲突 | 用户名/角色码不可复用；关联表若逻辑删除会撞索引 | 主表唯一索引取舍已列；关联表物理删除（无 deleted 字段） |
| 登录失败限流未走 Redis | 失败计数走 DB（多实例共享但粒度粗） | V1 接受；Redis 已因黑名单引入，V2 限流可平滑迁移 |
| 雪花 ID 回显精度丢失 | 前端 id 变形 | DO/VO 的 `Long id` 全部 `ToStringSerializer` |
| 开放注册无防灌水（无限流/验证码） | 脚本批量刷库、垃圾账号 | V1 接受（低风险场景）；V2 接入验证码或 IP 限流（Redis 已因黑名单就绪，可平滑复用） |
| 管理接口被越权调用 | 数据破坏 | system 域接口全部 `@PreAuthorize`（§7.4）；40300 双通路输出（`RestAccessDeniedHandler` + `GlobalExceptionHandler`，§10.1 第 5 项）+ 单测覆盖 |
