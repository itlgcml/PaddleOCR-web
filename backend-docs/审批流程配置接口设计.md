# 审批流程配置 · 后端接口设计

> 适用工程：`backend/`（JDK 8 + Spring Boot 2.7.18 + MyBatis-Plus 3.5.x + Druid 1.2.x + MySQL）
> 编写依据：现有 `ocr-common` / `ocr-client` / `ocr-dal` / `ocr-service` / `ocr-web` 分层与命名约定
> 前端依据：`frontend/src/views/approval/ProcessConfigView.vue`（流程配置列表）与 `frontend/src/views/approval/ProcessConfigEditView.vue`（两步向导：基本信息 + 流程设计）、`frontend/src/types/workflow.ts`（流程设计 JSON 结构）
> 目标：为「审批管理」补齐流程配置域的接口能力（流程定义 CRUD、流程设计 JSON 持久化、版本管理、草稿/发布/停用状态机）

### 1.1 术语与实体关系约定

| 实体 | 关系 | 说明 |
|---|---|---|
| `flow_process`（流程定义表） | —— | 一条流程定义一条记录，承载基本信息 + 状态 + 当前版本号 |
| `flow_process_version`（流程版本表） | 流程定义 : 版本 = **1 : n** | 每个版本存一份完整流程设计 JSON（`WorkflowDoc`），支持历史版本回溯 |

```
flow_process (1) ──< flow_process_version (n)     # process_id 逻辑外键（1:n）
```

## 2. 目标与范围

### 2.1 本期（V1）

1. **流程定义 CRUD**：新增（基本信息，初始草稿）、更新基本信息、分页查询、详情、逻辑删除（仅草稿态）。
2. **流程设计持久化**：保存流程设计 JSON（`WorkflowDoc`），查询流程设计（支持指定版本）。
3. **版本管理**：草稿保存 / 发布时递增版本（v1/v2/v3…），版本列表、按版本查询历史设计。
4. **状态机**：`DRAFT → PUBLISHED → DISABLED`，停用后可再发布；发布前服务端校验流程设计合法性（对齐前端 `useWorkflowValidate`）。
5. **权限**：流程配置域为管理端能力，全部接口 `@PreAuthorize("hasRole('ADMIN')")`。

### 2.2 明确不做（避免过度设计）

| 项 | 决策 | 理由 |
|---|---|---|
| 发起/待办/已办/待阅/已阅（前端二级菜单占位页） | V2 预留 | 本期聚焦「流程配置」域；发起、审批流转、我的申请等属流程运行态，需先有实例模型（`flow_instance`/`flow_task`），独立设计 |
| 流程实例运行引擎 | V2 | 需设计实例表、任务表、审批动作、条件/并行节点执行语义，量级大，另立专项 |
| 多人审批/条件分支的运行时计算 | V2 | 本期只存 `WorkflowDoc` JSON，不做节点级运行时解析与路由 |
| 流程设计可视化节点的服务端反序列化建模 | 不做 | 前端已用 JSON 自描述（`WorkflowDoc`），服务端以 `LONGTEXT` 存原文 + 发布时做最小结构校验，不逐节点落表 |
| 发起人范围与 `sys_role`/`sys_org` 的强关联外键 | 不做 | `initiators` 存 JSON 数组（前端为中文枚举：全体人员/部门负责人/指定角色/指定人员），由前端枚举约束；如需精确到角色/机构成员留 V2 |

## 3. 技术选型

| 能力 | 选型 | 放置 | 说明 |
|---|---|---|---|
| 持久层 | MyBatis-Plus `BaseMapper` | `ocr-dal` | 两张表各一个 DO + Mapper，无 join 需求不写 XML |
| 主键 | 雪花 ID `IdType.ASSIGN_ID` | `ocr-dal` | 与既有 `OrgDO` 等一致；`Long` 序列化为字符串 |
| 流程设计 JSON 存储 | `LONGTEXT` 列 | `flow_process_version.design_json` | 存 `WorkflowDoc` 完整 JSON，前后端契约零转换 |
| 发起人范围存储 | `VARCHAR(512)` 存 JSON 数组 | `flow_process.initiators` | 中文枚举数组 `["全体人员","部门负责人"]`；量级小无需关联表 |
| 状态/版本号存储 | `VARCHAR(16)` 英文枚举 | `status` / `version` / `current_version` | 与前端 `draft/published/disabled`、`v1/v2/v3` 契约一致，避免数字魔法值 |
| 分页 | `PageResultVO<T>` | `ocr-service/model` | 复用现有分页 VO |
| 接口鉴权 | `@PreAuthorize("hasRole('ADMIN')")` | `ocr-web` | 流程配置为管理端能力，复用现有 `SecurityConfig` 的方法级鉴权 |
| 接口文档 | springdoc `@Tag` / `@Operation` | `ocr-web` | 与既有 Controller 一致 |
| 防重复提交 | **Redisson 分布式锁** | `redisson-spring-boot-starter` 3.17.7（JDK 8 兼容线）→ `ocr-service` | 保存设计 / 发布接口用 `RLock` 对 `approval:process:submit:{id}` 加锁，`tryLock` 失败返回 40045；Redis 复用 auth 已引入实例 |

## 4. 数据模型设计

脚本：`backend/sql/03-approval-schema.sql`（两张表一次执行；`02` 编号已被 auth 占用，见 `backend-docs/用户注册与登录功能.md` §4）。

### 4.1 表：`flow_process`（审批流程定义表）

```sql
CREATE TABLE flow_process (
    id              BIGINT       NOT NULL COMMENT '雪花 ID',
    code            VARCHAR(64)  NOT NULL COMMENT '流程编码，业务唯一',
    name            VARCHAR(64)  NOT NULL COMMENT '流程名称',
    description     VARCHAR(255) DEFAULT NULL COMMENT '流程描述',
    initiators      VARCHAR(512) NOT NULL DEFAULT '[]' COMMENT '可发起人范围(JSON 数组，枚举：全体人员/部门负责人/指定角色/指定人员)',
    status          VARCHAR(16)  NOT NULL DEFAULT 'DRAFT' COMMENT '状态：DRAFT=草稿 PUBLISHED=已发布 DISABLED=已停用',
    current_version VARCHAR(16)  DEFAULT NULL COMMENT '当前版本号，如 v1；未保存过流程设计时为 NULL',
    create_time     DATETIME     NOT NULL COMMENT '创建时间',
    update_time     DATETIME     NOT NULL COMMENT '更新时间',
    deleted         TINYINT      NOT NULL DEFAULT 0 COMMENT '逻辑删除 0=未删 1=已删',
    PRIMARY KEY (id),
    UNIQUE KEY uk_code (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='审批流程定义表';
```

取舍：

- **`uk_code` 不含 `deleted`**：流程编码逻辑删除后不可复用，与 `sys_user.uk_username` 同策略，防"删后同名查到历史数据"。
- **`initiators` 用 JSON 文本列而非关联表**：发起人范围目前是 4 个中文枚举的「多选」，无跨表引用诉求；V2 若需精确到角色/机构成员再拆 `flow_process_initiator` 关联表。
- **`status` / `version` 用 `VARCHAR` 存英文枚举**：与前端契约（`draft/published/disabled`、`v1/v2/v3`）直映射，避免数字状态码在前后端各维护一份映射表。
- **`current_version` 冗余**：列表/详情直接回显当前版本号，避免每次 join 版本表；值由发布/保存草稿动作维护。

### 4.2 表：`flow_process_version`（审批流程版本表）

```sql
CREATE TABLE flow_process_version (
    id          BIGINT      NOT NULL COMMENT '雪花 ID',
    process_id  BIGINT      NOT NULL COMMENT '流程定义 ID',
    version     VARCHAR(16) NOT NULL COMMENT '版本号，如 v1/v2/v3',
    design_json LONGTEXT    NOT NULL COMMENT '流程设计 JSON(WorkflowDoc 完整结构)',
    status      VARCHAR(16) NOT NULL DEFAULT 'DRAFT' COMMENT '版本状态：DRAFT=草稿 PUBLISHED=已发布',
    create_time DATETIME    NOT NULL COMMENT '创建时间',
    update_time DATETIME    NOT NULL COMMENT '更新时间',
    deleted     TINYINT     NOT NULL DEFAULT 0 COMMENT '逻辑删除 0=未删 1=已删',
    PRIMARY KEY (id),
    UNIQUE KEY uk_process_version (process_id, version),
    KEY idx_process_id (process_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='审批流程版本表';
```

取舍：

- **`design_json` 存 `WorkflowDoc` 原文**：前端可视化设计器产出的 `{ name, updatedAt, root }` 完整 JSON；服务端只做最小结构校验（§7.4），不逐节点落表。
- **`uk_process_version(process_id, version)`**：一个流程同一版本号唯一，版本号由服务端单调递增生成，防并发重复。
- **已发布版本不可变（immutable）**：发布后 `design_json` 不再允许原地覆盖，编辑必须新开版本；由 Service 层语义保证（发布态的版本记录禁止 update 设计 JSON）。

### 4.3 状态机与版本策略

**状态机**：

```
        publish                 disable
 DRAFT ────────▶ PUBLISHED ──────────────▶ DISABLED
   ▲                                         │
   └─────────────── publish ─────────────────┘
```

| 当前状态 | 允许动作 |
|---|---|
| `DRAFT` | 编辑基本信息、保存/覆盖草稿设计、发布、删除 |
| `PUBLISHED` | 停用、查看（不可编辑基本信息/设计，编辑需停用或新开草稿） |
| `DISABLED` | 再发布（回到 `PUBLISHED`）、查看 |

> 简化约定：**仅 `DRAFT` 态可写**（基本信息 + 流程设计）。`PUBLISHED` 态如需修改，前端走「停用 → 修改 → 再发布」或后续版本增量；V1 不做"已发布态原地编辑"，避免引入"运行中流程被改"的语义复杂度。

**版本策略**：

| 动作 | 版本行为 |
|---|---|
| 新增流程 | 无版本，`current_version = NULL`，状态 `DRAFT` |
| 保存流程设计（草稿） | 若 `current_version` 对应版本状态仍为 `DRAFT` → 覆盖其 `design_json`；否则新增版本 `v{n+1}` 并更新 `current_version` |
| 发布 | 校验 `design_json` 合法（§7.4）→ 将 `current_version` 对应草稿版本标记为 `PUBLISHED` → 流程状态置 `PUBLISHED` |
| 再发布（DISABLED→PUBLISHED） | 复用当前版本设计 JSON，仅改状态，不生成新版本 |

## 6. 错误码设计

`ResultCode` 追加（沿用分段：0 成功 / 4xxxx 客户端 / 5xxxx 系统 / 503xx OCR），审批流程段取 **40040 起**：

| 枚举 | code | message | 触发场景 |
|---|---|---|---|
| `PROCESS_CODE_EXISTS` | 40040 | 流程编码已存在 | 新增流程撞 `uk_code`（含并发兜底） |
| `PROCESS_NOT_FOUND` | 40041 | 流程不存在 | 目标流程查无/已删 |
| `PROCESS_DESIGN_INVALID` | 40042 | 流程设计不合法 | 发布时 `design_json` 未通过最小结构校验（§7.4） |
| `PROCESS_STATUS_ILLEGAL` | 40043 | 流程状态不允许该操作 | 非 `DRAFT` 态编辑/删除；非 `PUBLISHED` 态停用 |
| `PROCESS_VERSION_NOT_FOUND` | 40044 | 流程版本不存在 | 按版本查询设计时查无该版本 |
| `PROCESS_REPEAT_SUBMIT` | 40045 | 请勿重复提交 | 保存设计 / 发布接口并发重复提交（分布式锁未获取） |

**HTTP 状态码策略**：业务响应一律 HTTP 200 + `code` 非零；鉴权失败沿用现有 401/403 通路（`code` ∈ 40100~40103/40300），本章节不重复。并发撞唯一索引由 `GlobalExceptionHandler` 的 `DuplicateKeyException` 映射 `uk_code → 40040`、`uk_process_version → 40042`（版本号生成冲突按系统异常处理，见 §13）。

## 7. 核心类设计

### 7.1 `ocr-dal`：两张表实体类

**注解规范**（与既有 DO 一致）：表名 `@TableName`、表中文名类级 `@Schema`、字段中文名 + 长度字段级 `@Schema`、主键 `@TableId(type = IdType.ASSIGN_ID)` + `@JsonSerialize(ToStringSerializer)`、审计字段 `@TableField(fill = ...)`、逻辑删除 `@TableLogic`。

#### `ProcessDO`（`flow_process`，审批流程定义表）

```java
@Data
@TableName("flow_process")

public class ProcessDO implements Serializable {

    @Schema(description = "流程定义 ID（雪花 ID）")

    @Schema(description = "流程描述", maxLength = 255)
    private String description;

    @Schema(description = "可发起人范围(JSON 数组)", maxLength = 512)
    private String initiators;

    @Schema(description = "状态：DRAFT=草稿 PUBLISHED=已发布 DISABLED=已停用", maxLength = 16)
    private String status;

    @Schema(description = "当前版本号，如 v1", maxLength = 16)
```

### 7.4 发布校验（`design_json` 最小结构校验，对齐前端 `useWorkflowValidate`）

发布时对 `design_json`（`WorkflowDoc`）做**最小结构校验**，任一不满足抛 `BusinessException(PROCESS_DESIGN_INVALID)`：

| 规则 | 对应前端逻辑 |
|---|---|
| `design_json` 非空且可解析为 `{ name, root }` | `loadDoc` 的基础校验 |
| `root.type == "START"` | 前端 `loadDoc` 要求根节点为 START |
| 遍历节点：`name` 非空 | `useWorkflowValidate` 的「存在未命名的节点」 |
| 遍历节点：`APPROVER` 节点 `source ∈ {MEMBER,ROLE}` 时 `memberIds` 非空 | 「审批节点未选择审批人」 |
| `CONDITION` 节点：非 `isDefault` 且无规则 → 报错 | 「条件未配置规则」 |

> 校验用通用 JSON 解析（`com.fasterxml.jackson` 或 `org.json`），**不逐节点建 Java 模型**；只做"能否通过"判断，不解析节点语义（V2 运行时引擎再深挖）。

### 7.5 防重复提交（Redisson 分布式锁）

「保存流程设计」「发布」为**非幂等写操作**，需防重复提交（双击 / 网络重试导致同请求并发到达）：

- **锁维度**：`approval:process:submit:{processId}`（保存与发布共用同一把锁，串行化对同一流程的写操作）
- **获取方式**：`RLock#tryLock(0, 3, TimeUnit.SECONDS)`（`waitTime=0` 不等待立即返回；`leaseTime=3s` 自动释放兜底，防业务异常未 unlock 导致死锁）
- **获取失败** → 抛 `BusinessException(PROCESS_REPEAT_SUBMIT)`（40045）
- **释放**：`finally` 中 `lock.isHeldByCurrentThread() && lock.unlock()`，防误删他人持有的锁
- **Redis 实例**：复用 auth 已引入的 Redis（与 `TokenBlacklistService` 同实例），Boot 2.7 前缀 `spring.redis.*`

```java
// ProcessServiceImpl 示意
RLock lock = redissonClient.getLock("approval:process:submit:" + processId);
if (!lock.tryLock(0, 3, TimeUnit.SECONDS)) {
    throw new BusinessException(ResultCode.PROCESS_REPEAT_SUBMIT);
}
try {
    // 保存设计 / 发布逻辑
} finally {
    if (lock.isHeldByCurrentThread()) {
        lock.unlock();
    }
}
```

## 8. 安全设计要点

| 主题 | 设计 |
|---|---|
| 垂直越权 | 流程配置域为管理端能力，Controller 全部 `@PreAuthorize("hasRole('ADMIN')")`；非 ADMIN 返回 40300（复用现有 `RestAccessDeniedHandler` / `GlobalExceptionHandler` 双通路） |
| 鉴权 | 复用现有 JWT 过滤器链，无需新增；接口仅需在 `SecurityConfig` 白名单之外（默认已 `/api/**` 需认证） |
| SQL 注入 | 全部 `LambdaQueryWrapper`；`keyword` 模糊查询用 `like` 包装器参数，禁止 `apply`/`last` 拼接 |
| 并发唯一 | 新增撞 `uk_code` 由 `DuplicateKeyException` 映射 40040；版本号生成在 `ProcessService#saveDesign` 内用 `uk_process_version` 兜底 |
| JSON 注入/超大负载 | `design_json` 为服务端校验后存储；DTO 对 `designJson` 做长度上限校验（如 ≤ 512KB），防超大 JSON 拖垮接口 |
| 状态机约束 | 所有写操作先 `selectById` 判断当前状态再执行；状态判断与更新同事务（`@Transactional(rollbackFor = Exception.class)`），防并发下的非法流转 |
| 越权数据 | `processId` 来自路径，Service 统一 `selectById` 校验存在性 + `deleted=0`（逻辑删除自动过滤），不存在返回 40041 |
| 防重复提交 | 保存设计 / 发布接口用 Redisson 分布式锁 `approval:process:submit:{id}` 串行化；`tryLock` 失败返回 40045；`leaseTime=3s` 兜底防死锁 |

## 9. API 设计（全接口出入参）

统一前缀 `/api/approval/process`，返回 `ApiResponse<T>`（`code/message/data/timestamp`），**下文"响应"仅描述 `data` 部分**。通用约定：

- 所有 `Long` 类型 id 在 JSON 中**一律为字符串**（`ToStringSerializer`）；
- 时间字段格式 `yyyy-MM-dd HH:mm:ss`（GMT+8）；
- 参数校验失败统一返回现有 `40000`（`MethodArgumentNotValidException`）；
- 全部接口需 ADMIN 角色（`@PreAuthorize`），鉴权失败返回 `40300`，下文不再重复。

### 9.3 新增流程 `POST /api/approval/process/create`

请求 Body（`ProcessSaveDTO`）：

请求：路径参数 `id`；Body（`ProcessUpdateDTO`）：

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|

| initiators | string[] | 是 | 非空，元素同上 | 可发起人范围 |

### 9.5 保存流程设计 `PUT /api/approval/process/design/{id}`

请求：路径参数 `id`；Body（`ProcessDesignSaveDTO`）：

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| designJson | string | 是 | 非空，≤ 512KB | `WorkflowDoc` 完整 JSON 字符串 |

服务端动作（仅 `DRAFT` 态）：解析 `designJson` 做基础结构校验（§7.4 的解析性校验，不含发布级规则）→ 按版本策略（§4.3）覆盖当前草稿版本或新开版本 `v{n+1}` → 更新 `current_version`。

响应 `data`：`string`，本次保存的版本号（如 `v1`）。

失败：`40041` 不存在、`40043` 非 DRAFT 态、`40042` JSON 不可解析或结构不合法、`40045` 重复提交（分布式锁未获取）。

请求：路径参数 `id`；Query：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| version | string | 否 | 指定版本号，如 `v2`；缺省取 `current_version` |

响应 `data`（`ProcessDesignVO`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| version | string | 版本号 |
| status | string | 版本状态 `DRAFT`/`PUBLISHED` |
| designJson | string | `WorkflowDoc` JSON 字符串（前端直接反序列化） |
| updateTime | string | 该版本更新时间 |

失败：`40041` 不存在、`40044` 指定版本不存在。

### 9.7 发布流程 `POST /api/approval/process/publish/{id}`

请求：路径参数 `id`，无 Body。

服务端动作：校验 `current_version` 存在 → 对当前草稿版本 `design_json` 做**发布级完整校验**（§7.4）→ 校验通过则将版本置 `PUBLISHED`、流程状态置 `PUBLISHED`；校验失败返回 `PROCESS_DESIGN_INVALID`。

响应：`data` 为 `null`。

失败：`40041` 不存在、`40043` 状态不允许（仅 DRAFT/DISABLED 可发布）、`40042` 设计不合法、`40044` 无可用草稿版本、`40045` 重复提交（分布式锁未获取）。

### 9.8 停用流程 `POST /api/approval/process/disable/{id}`

请求：路径参数 `id`，无 Body。服务端动作：仅 `PUBLISHED` 态 → 置 `DISABLED`。

响应：`data` 为 `null`。失败：`40041` 不存在、`40043` 非 PUBLISHED 态。

### 9.9 版本列表 `GET /api/approval/process/versions/{id}`

请求：路径参数 `id`，无 Query。

响应 `data`（`ProcessVersionVO[]`，按版本号降序）：

| 字段 | 类型 | 说明 |
|---|---|---|
| version | string | 版本号 |
| status | string | `DRAFT`/`PUBLISHED` |
| updateTime | string | 该版本更新时间 |

失败：`40041` 不存在。

### 9.10 删除流程 `DELETE /api/approval/process/delete/{id}`

请求：路径参数 `id`，无 Body。服务端动作：仅 `DRAFT` 态 → 逻辑删除（连带逻辑删除其版本记录）。

响应：`data` 为 `null`。失败：`40041` 不存在、`40043` 非 DRAFT 态。

> 前端当前操作列未暴露删除按钮，本接口为后端预留能力（草稿态清理），是否暴露由前端后续决定。

## 13. 风险与取舍

| 风险 | 影响 | 应对 |
|---|---|---|
| 流程设计 JSON 服务端不建模 | 无法做节点级强校验 | 本期做最小结构校验（§7.4）；运行时引擎（V2）再引入节点级建模与语义校验 |
| `initiators` 存 JSON 文本 | 无法按发起人范围做 DB 级过滤 | V1 范围仅为 4 个中文枚举，前端约束；V2 精确到角色/机构成员时拆关联表 |
| 已发布版本不可原地改 | 运行态流程改动需新版本 | 明确语义：编辑需新开草稿版本（§4.3），避免"运行中被改" |
| 版本号并发生成冲突 | 撞 `uk_process_version` | 版本号由 `current_version` 单调递增 + 唯一索引兜底；冲突重试或返回系统异常 |
| 状态判断与更新并发 | 非法流转 | 状态机写操作同事务 + 先查后改（`@Transactional`），配合状态枚举收敛 |
| `design_json` 超大负载 | 接口被大 JSON 拖垮 | DTO 长度上限校验（默认 512KB，§10 可配） |
| 雪花 ID 回显精度丢失 | 前端 id 变形 | DO/VO 的 `Long id` 全部 `ToStringSerializer`（§7.1） |
| 管理接口越权 | 数据破坏 | Controller 全部 `@PreAuthorize("hasRole('ADMIN')")`（§8） |
| Redisson 锁依赖 Redis 可用性 | 防重复提交失效 | `tryLock` 在 Redis 不可用时按可重试错误处理（不静默放行写操作）；锁 `leaseTime=3s` + `finally` 释放兜底防死锁 |
