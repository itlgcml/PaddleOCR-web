# 流程设计器（workflow-design）前端设计文档

> 本文档基于 `frontend/src` 中 `/workflow-design` 画布的现有实现逆向整理，可直接作为重新生成该模块代码的依据。

## 1. 概述

### 1.1 功能定位

钉钉/飞书风格的**审批流程可视化设计器**：画布以「节点卡片 + 连线」纵向呈现流程链路，支持点击节点修改属性、点击「+」插入节点、条件分支/并行分支的多列编辑，以及草稿保存、JSON 导入导出与流程校验。

- 路由：`/workflow-design`，`name: 'WorkflowDesign'`，`meta: { requiresAuth: true, title: '流程设计' }`
- 页面组件：`src/views/system/WorkflowDesignView.vue`
- 技术栈：Vue 3.5（`<script setup>` + Composition API）+ TypeScript 5.9 + Pinia 4 + Element Plus 2.14（按需自动导入，`ElMessage`/`ElMessageBox` 为全局注入）

## 2. 数据模型（`src/types/workflow.ts`）

### 2.1 节点类型枚举

```ts
export enum NodeType {
  START = 'START',                    // 发起人（根节点，固定 1 个，不可删/复制）
  APPROVER = 'APPROVER',              // 审批人
  CONDITIONS = 'CONDITIONS',          // 条件分支（容器，自身无卡片）
  CONDITION = 'CONDITION',            // 条件分支列（容器的列）
  PARALLEL = 'PARALLEL',              // 并行节点（容器，无默认列，多列同时执行）
  PARALLEL_BRANCH = 'PARALLEL_BRANCH',// 并行分支列
  TRANSACT = 'TRANSACT',              // 办理人
}
```

- 结束节点**不在数据结构中**，由画布静态渲染。
- `isBranchContainer(type)`：`CONDITIONS || PARALLEL`（分支容器，横向展开多列）。
- `isBranchNode(type)`：容器或分支列（`CONDITIONS/PARALLEL/CONDITION/PARALLEL_BRANCH`）——**分支节点之下不允许直接再挂分支容器**（添加菜单中据此过滤掉分支类选项）。

### 2.2 递归节点结构

```ts
export interface WorkflowNode {
  id: string                    // crypto.randomUUID()，降级 wf-{ts}-{rand}
  name: string
  type: NodeType
  props: NodeProps
  childNode: WorkflowNode | null        // 主干纵向串联
  conditionNodes?: WorkflowNode[]       // 分支横向展开（仅容器有）
}

export interface WorkflowDoc {
  name: string          // 流程名称（工具栏可编辑）
  updatedAt: number
  root: WorkflowNode    // 恒为 START 类型
}
```

### 2.3 各类型节点属性

**发起人 `StartProps`**

| 字段 | 类型 | 说明 |
|---|---|---|
| rangeType | `'ALL' \| 'MEMBER' \| 'ROLE'` | 可发起人范围 |
| memberIds | `string[]` | 指定成员/角色 id 列表 |

**审批人 `ApproverProps`**

| 字段 | 类型 | 说明 |
|---|---|---|
| source | `'MEMBER' \| 'LEADER' \| 'ROLE' \| 'SELF_SELECT' \| 'INITIATOR'` | 审批人来源 |
| memberIds | `string[]` | MEMBER/ROLE 时的选择结果 |
| leaderLevel | `number`（1-10） | LEADER 时的主管层级 |
| multiMode | `'OR' \| 'AND'` | 或签 / 会签 |
| emptyPolicy | `'AUTO_PASS' \| 'TO_LEADER' \| 'TO_ADMIN'` | 审批人为空策略 |
| canRejectToStart | `boolean` | 允许退回发起人 |

**条件分支列 `ConditionProps`**（支持多条件组，组内、组间均可用「且/或」）

```ts
interface ConditionRule {
  fieldKey: string; fieldName: string
  operator: 'EQ'|'NEQ'|'GT'|'GTE'|'LT'|'LTE'|'CONTAIN'|'NOT_CONTAIN'
  value: string
  link: 'AND' | 'OR'          // 与同组上一条规则的连接符，组内首条忽略
}
interface ConditionGroup {
  name: string                // 可编辑，默认「组n」（跳过已占用序号）
  link: 'AND' | 'OR'          // 与上一组的连接符，首个组忽略
  rules: ConditionRule[]
}
interface ConditionProps { groups: ConditionGroup[]; isDefault: boolean }
```

- 默认条件列（`isDefault: true`）：固定位于最右一列，名称恒为「其他条件」，名称输入框禁用，不配置规则，卡片摘要为「其余条件均不满足时进入」。

**其余类型**（CONDITIONS/PARALLEL/PARALLEL_BRANCH/TRANSACT）`props` 为空对象。

### 2.4 默认属性工厂与默认名称

```ts
createNodeProps(type): NodeProps
// START → { rangeType:'ALL', memberIds:[] }
// APPROVER → { source:'MEMBER', memberIds:[], leaderLevel:1, multiMode:'OR',
//              emptyPolicy:'AUTO_PASS', canRejectToStart:false }
// CONDITION → { groups:[], isDefault:false }
// 其余 → {}
```

默认名称：发起人 / 审批人 / 条件分支 / 条件 / 并行节点 / 并行分支 / 办理人。

节点卡片与条件头的图标/配色：

| 类型 | Element 图标 | 主题色 |
|---|---|---|
| START | User | `#409EFF` |
| APPROVER | Avatar | `#FF9438` |
| CONDITIONS / CONDITION | Share | `#8A94E6` |
| TRANSACT | EditPen | `#6C7CFF` |
| PARALLEL（添加菜单项） | — | `#7C6BFF` |

## 3. 交互设计（点击修改）

### 3.1 画布整体交互

- **缩放**：0.5–2，步长 0.1，`transform: scale()`（origin top center），store 中按 0.1 取整；工具栏显示百分比，「适应画布」重置为 100%。
- **点击空白**：画布与页面根元素的 `@pointerdown` 统一调用 `store.closeAddMenu()`，全局最多只展开一个「添加节点」菜单。
- **连线为纯 CSS 绘制**（绝对定位的 2px 竖线/横线，颜色 `#dedfdf`），不依赖 JS 测量或画图库。实体层 `z-index: 1`、连线层 `z-index: 0`、菜单 `z-index: 20`。

### 3.2 节点卡片（NodeCard）点击操作

| 操作 | 触发 | 行为 |
|---|---|---|
| 打开属性抽屉 | 点击卡片任意处 | `store.setActive(id)` → 弹出 NodePropDrawer（卡片高亮 `is-active`） |
| 复制 | 卡片头部悬浮出现的复制图标（`hover` 才显示） | 深拷贝子树并重生成全部 id，插到原节点之后；START 不可复制 |
| 删除 | 卡片头部悬浮出现的删除图标 | `ElMessageBox.confirm`（提示「连同其内部子流程一并删除」）确认后删除；后继自动接驳到父级；START 不可删除 |

卡片描述摘要逻辑：

- START：`rangeType === 'ALL'` → 「所有人」，否则为所选成员/角色名拼接（空则「请设置」）
- APPROVER：LEADER → 「直属主管 / 连续 N 级主管」；INITIATOR → 「发起人本人」；SELF_SELECT → 「发起人自选」；MEMBER/ROLE → 成员名拼接（空则「请设置审批人」）
- CONDITION：`isDefault` → 「其余条件均不满足时进入」；否则按「组内规则以各条 link 串联、多规则组加括号、组间以组 link 串联」生成摘要（如 `报销金额 > 1000 且 所属部门 = 财务`），空则「请设置条件」

### 3.3 添加节点（AddNodeButton）

- 外观：连线中点上的 28px 圆形「+」按钮，hover 放大变蓝；上下各补一段连线。
- 点击弹出菜单（无遮罩层，外部点击由画布 pointerdown 关闭；菜单内部 `pointerdown.stop` 防止先被画布关闭），菜单项：

| 项 | 类型 | 圆点颜色 |
|---|---|---|
| 审批人 | APPROVER | `#FF9438` |
| 条件分支 | CONDITIONS | `#8A94E6` |
| 并行节点 | PARALLEL | `#7C6BFF` |

- 若父节点是分支节点（`isBranchNode`），菜单只保留「审批人」。
- 选中后：新节点挂到 `parent.childNode` 之前（原后继接在新节点之后）；**分支容器创建后不弹属性抽屉**（容器无属性表单），普通节点创建后立即打开抽屉。
- 幂等处理：菜单项 `mousedown.prevent` + `click` 双路径触发，通过 `visible` 判断只执行一次。

**初始形态（钉钉式）**：

- 新建条件分支容器：两列「条件1 + 其他条件」，`isDefault` 标记最右列，每列预置 1 个审批人节点。
- 新建并行节点容器：固定 2 列「并行1 / 并行2」（无默认列），每列预置 1 个审批人节点。

### 3.4 分支容器（NodeChain 分支区）

容器自身不渲染卡片，渲染为多列结构；每列自上而下为：分流横线段 → 条件头 → 条件头连线 → 列内子链（递归 NodeChain）→ 列底出线（自适应撑满）→ 汇合横线段。

**条件头（虚线框，min-width 180px）**：点击打开该列的属性抽屉；悬浮出现操作图标：

| 图标 | 动作 | 可用性 |
|---|---|---|
| ⇤ DArrowLeft | 移动到最左 | `idx > 0` |
| ← ArrowLeft | 左移一级 | `idx > 0` |
| → ArrowRight | 右移一级 | `idx < len-1` |
| ⇥ DArrowRight | 移动到最右 | `idx < len-1` |
| ✕ Close | 删除分支 | 多列时默认条件列不可删（置灰 not-allowed） |

- 列头标题：分支列名称（条件1/条件2…、其他条件、并行1…），紫色 `#8A94E6` 加粗。
- 移动/增删列之后统一调用 `normalizeBranches` 按位置重建编号与默认身份（**会覆盖自定义名称**）：条件分支末列为「其他条件」，其余为「条件n」；并行全部为「并行n」。

**添加列**：分支区顶部居中的「添加条件 / 添加并行分支」按钮（位于分流横线正中上方）；新列插入默认列之前（并行尾插），预置 1 个审批人节点，并打开该列属性抽屉。

**删除列（`resolveBranchDeleteAction` 决定确认文案）**：

| 动作 | 触发条件 | 确认文案 |
|---|---|---|
| `COLUMN` | 多列（>2）时删非默认列 | 「删除该分支列将连同其内部子流程一并删除，确定吗？」 |
| `BRANCH` | 条件分支仅剩 2 列时任列删除 | 「删除会连同整个条件分支节点及其内部子流程一并移除…」 |
| `PARALLEL` | 并行节点仅剩 2 列时任列删除 | 「删除会连同整个并行节点及其内部子流程一并移除…」 |
| `NONE` | 多列时删默认条件列 | 提示「其他条件列不可删除」，不发请求 |

删除整容器时主干自动接驳（容器 `childNode` 顶上来），同时收起属性抽屉。

**嵌套规则**：分支列内可继续通过「+」添加审批人，但分支列下不能直接挂分支容器（菜单过滤）；分支容器汇合后的主干可继续挂任意节点。

### 3.5 工具栏（WorkflowToolbar）

| 控件 | 行为 |
|---|---|
| 流程名称输入（maxlength 30，prepend「流程名称」） | `v-model:flow-name` 直接写回 `doc.name` |
| 缩放 − / 百分比 / ＋ / 适应画布 | `v-model:zoom`，−/+ 步长 0.1，范围 0.5–2；适应画布 = 重置 100% |
| 校验 | 调 `useWorkflowValidate` 的 `errors`；无错提示「校验通过」，有错提示首条错误并 `setActive` 定位到出错节点 |
| 导入 | 隐藏 `<input type="file" accept=".json">`，读文件文本 → `store.loadDoc`；成功关抽屉提示「导入成功」，失败提示「导入失败：JSON 结构不合法」 |
| 导出 | `store.exportDoc()` 生成 JSON Blob，`a[download]` 下载，文件名 `{流程名}.json` |
| 重置 | confirm「将清空当前流程并恢复为初始模板」→ `store.resetDoc()` |
| 保存草稿（primary） | `store.saveDraft()` 写 localStorage，提示「已保存到本地草稿」 |

### 3.6 属性抽屉（NodePropDrawer）

- `el-drawer`，`size: 560px`，`append-to-body`、`destroy-on-close`，`v-model` 控制显隐。
- 标题映射：发起人 / 审批人 / 条件规则 / 并行分支，默认「节点配置」。
- **编辑草稿模式**：打开时对 `node.props` 深拷贝为草稿（START/APPROVER/CONDITION 各一份独立 draft ref），**保存时一次性提交**，取消/关闭不污染画布数据。
- 表单按类型渲染（见 2.3 字段），公共项「节点名称」（maxlength 20；条件默认列禁用）。
- 条件编辑：多条件组卡片（浅灰底卡片 `#fafbfc`），组头为组名输入 + 删除组图标；组间、组内各有居中的「且/或」下拉（72px）；规则行 = 字段下拉(104px) + 操作符下拉(104px) + 值输入(flex) + 圆形删除按钮；底部「添加条件组」整宽按钮。默认条件列只显示 info alert「其他条件：其余分支均不满足时进入，无需配置规则」。
- 保存：条件节点若 `isDefault` 强制命名「其他条件」。

### 3.7 校验规则（useWorkflowValidate）

computed 先序递归遍历，返回 `WorkflowError[] { nodeId, message }`：

1. 节点名称为空 → 「存在未命名的节点」
2. APPROVER：source 为 MEMBER/ROLE 且 memberIds 为空 → 「审批节点「x」未选择审批人」
3. CONDITION：非默认列且规则总数（各组 rules 之和）为 0 → 「条件「x」未配置规则」
4. CONDITIONS 容器：无任何分支列 → 「条件分支不存在任何分支列」

## 4. Store 设计（`src/stores/workflow.ts`，setup 风格）

### 4.1 State / Computed

| 名称 | 类型 | 说明 |
|---|---|---|
| doc | `Ref<WorkflowDoc>` | 初始为 localStorage 草稿（经 sanitize）或「未命名流程 + 发起人」模板 |
| zoom | `Ref<number>` | 缩放，0.5–2 |
| activeNodeId | `Ref<string \| null>` | 当前抽屉打开的节点 |
| addMenuId | `Ref<string \| null>` | 当前展开「+」菜单的 parentId（全局唯一） |
| activeNode | `ComputedRef<WorkflowNode \| null>` | 按 activeNodeId 先序查找 |

### 4.2 Actions

| Action | 说明 |
|---|---|
| `insertNode(parentId, type)` | 插入节点到 parent.childNode 前；CONDITIONS/PARALLEL 按初始形态建列并预置审批人；START 不可插，失败返回 null |
| `deleteNode(id)` | 根不可删；从父级摘除（childNode 直接接驳 / conditionNodes splice） |
| `copyNode(id)` | 深拷贝子树 + 全部 id 重生成，`copy.childNode = target.childNode`，替换父级指向；START 不可复制 |
| `updateNode(id, props, name?)` | 更新属性与名称（空名不覆盖） |
| `addBranch(containerId)` | 加列（插在默认列前 / 并行尾插），预置审批人，normalize |
| `deleteBranch(id)` | 按 resolveBranchDeleteAction 删列或删整容器 |
| `resolveBranchDeleteAction(id)` | 返回 `COLUMN \| BRANCH \| PARALLEL \| NONE`（最小列数 `MIN_BRANCH_COLUMNS = 2`） |
| `moveBranch(id, action)` | FIRST/PREV/NEXT/LAST 重排后 normalize |
| `setActive(id \| null)` / `openAddMenu(id)` / `closeAddMenu()` | UI 状态 |
| `setZoom(value)` | clamp 0.5–2，0.1 取整 |
| `resetDoc()` | 恢复默认模板，清空 active/menu/zoom |
| `loadDoc(json)` | JSON.parse → 必须含 `root` 且 `root.type === 'START'` → sanitizeDoc；失败返回 false |
| `exportDoc()` | 刷新 updatedAt，返回格式化 JSON 字符串 |
| `saveDraft()` | exportDoc 写入 `localStorage['workflow-draft']`，异常静默 |

### 4.3 查找与兼容工具（模块内私有）

- `findNode(node, id)`：先序遍历主干 + 分支列。
- `findParent(node, id)`：childNode 直属或 conditionNodes 中的父（含递归）。
- `cloneWithNewIds`：深拷贝子树，props deepClone，全部 id 重生成。
- `normalizeBranches(containerType, branches)`：按位置重建默认身份与名称。
- **旧草稿兼容 sanitize**（loadDoc / restoreDraft 均调用）：
  - 剔除已不被枚举支持的类型节点，把其后继接驳到父级（先清子树再判自身）；整树被剔空时退回新发起人节点；
  - 条件属性迁移：旧单层 `rules` 结构 → 迁移为一个条件组 `{ name:'组1', link:'AND', rules }`，缺失的 `link` 补 `'AND'`，缺失组名/连接符补默认值。

## 5. 渲染与样式要点

### 5.1 画布（WorkflowCanvas）

- 灰底点阵：`background: #f5f6f7` + `radial-gradient(#e3e5e8 1px, transparent 1px)`，`background-size: 16px 16px`；`overflow: auto`。
- 缩放层 `.wf-canvas-scale`：`transform: scale(zoom)`，origin top center，`min-width: 100%`，padding `40px 24px 80px`。
- 流程列 `.wf-canvas-flow`：纵向 flex 居中，`width: fit-content; min-width: 100%` 居中。
- 结束节点：小圆点（10px，`#909399` 底 + `#dedfdf` 描边）+ 「流程结束」文案，静态渲染。

### 5.2 递归链（NodeChain）

- 普通节点 = `NodeCard` + `AddNodeButton`；分支容器 = 多列 + 列尾「+」+ 主干后继递归。
- **连线全部为 CSS**：
  - 容器入口竖线 44px（`::before`）、出口竖线 20px（`::after`），均居中 2px 宽；
  - 分流/汇合横线由每列自绘一段（`.wf-branch-hr` top:-24px / `.wf-branch-join` bottom:0），相邻列在 24px 列间 padding 处首尾相接；仅多列时端点列收口到自身列中心（`.is-first > hr/join { left:50% }`、`.is-last { right:50% }`，必须用直接子级选择器避免嵌套分支误伤）；
  - 列底出线 `.wf-branch-col-out` 用 `flex: 1 1 auto` 自适应撑满长短列，保证都连到汇合横线。
- 列与容器均 `width: max-content; flex-shrink: 0`，保证嵌套分支时列中心不漂移、横线端点不错位。
- 容器 body 上内边距 68px = 入口竖线 44 + 列进线 24，其中预留「添加条件」按钮高度。

### 5.3 组件事件流

组件不直接操作数据，所有事件经 `$attrs` 逐层透传（`WorkflowCanvas` 与 `NodeChain` 均设置 `defineOptions({ inheritAttrs: false })`），最终由 `WorkflowDesignView` 统一接住并调用 store：

```
NodeCard/AddNodeButton/NodeChain ──(open/add/copy/remove/add-branch/del-branch/move-branch)──▶
WorkflowCanvas(v-bind=$attrs) ──▶ WorkflowDesignView ──▶ store + ElMessage/ElMessageBox
```

| 事件 | 签名 | View 侧处理 |
|---|---|---|
| open | `(node)` | setActive + 打开抽屉 |
| add | `(parentId, type)` | insertNode；分支容器不弹抽屉，否则 onOpen |
| copy | `(id)` | copyNode，失败报错 |
| remove | `(id)` | confirm → 删除，命中 active 时收起抽屉 |
| add-branch | `(containerId)` | addBranch → 打开新列抽屉 |
| del-branch | `(id)` | resolve 动作 → 不同 confirm 文案 → deleteBranch |
| move-branch | `(id, action)` | moveBranch |
| save（抽屉） | `(id, props, name)` | updateNode + setActive(null) |
