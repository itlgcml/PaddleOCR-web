# 审批流前端设计文档（仿钉钉流程设计器）

> 版本：v1.0　日期：2026-09-28
> 范围：**纯前端效果实现**（不依赖后端，数据支持本地导入/导出 JSON，预留 API 位）
> 视觉与交互基准：钉钉 OA「审批流程设计器」（垂直树状结构，非自由拖拽画布）

---

## 1. 概述

### 1.1 目标

在 PaddleOCR-web 前端（Vue 3.5 + TS 5.9 + Element Plus 2.14 + Pinia 4）实现仿钉钉的可视化审批流程设计器：

- 垂直串联的**树状流程画布**（发起 → 审批/抄送 → 条件分支 → 结束），非自由连线 DAG；
- 节点间「+」按钮快捷添加节点，点击弹出节点类型菜单；
- 点击节点卡片，**右侧滑出抽屉**配置属性；
- 条件分支横向多列并排，支持优先级排序、默认分支（ELSE）、增删分支；
- 画布支持缩放/适应、整体校验、JSON 导入导出。

### 1.2 非目标（本期不做）

- 节点自由拖拽连线（钉钉本身也不是自由画布）；
- 流程后端部署/流转（仅预留接口契约，见第 9 节）；
- 与钉钉服务器互通。

| `END` | 结束 | 灰 `#909399` | 静态渲染 | 不入数据结构 |

- 宽 `220px`，白底，圆角 `4px`，内边距 `12px`；hover 阴影 `0 2px 8px rgba(0,0,0,.12)` + 描边高亮；

- 竖向连接线 `2px solid #DEDFDF`，高 `40px`；

## 4. 数据结构设计

钉钉式**单链递归树**：主干 `childNode` 串联，分支容器 `conditionNodes[]` 横向展开，每列内部又是一条链。

### 4.1 类型定义（`src/types/workflow.ts`）

```ts
export enum NodeType {
  START = 'START', APPROVER = 'APPROVER', CC = 'CC',
  CONDITIONS = 'CONDITIONS', CONDITION = 'CONDITION', TRANSACT = 'TRANSACT',
}

export type ApproverSource = 'MEMBER' | 'LEADER' | 'ROLE' | 'SELF_SELECT' | 'INITIATOR';
export type MultiApproverMode = 'OR' | 'AND';                  // 或签 / 会签
export type EmptyApproverPolicy = 'AUTO_PASS' | 'TO_LEADER' | 'TO_ADMIN';
export type ConditionOperator =
  | 'EQ' | 'NEQ' | 'GT' | 'GTE' | 'LT' | 'LTE'
  | 'CONTAIN' | 'NOT_CONTAIN' | 'IN' | 'NOT_IN';

export interface ConditionRule {
  fieldKey: string; fieldName: string;
  operator: ConditionOperator; value: string;   // 值统一字符串存储
}

export interface ApproverProps {
  source: ApproverSource;
  memberIds: string[];          // ID 一律 string
  leaderLevel: number;          // 1=直属主管，2=连续多级
  multiMode: MultiApproverMode;
  emptyPolicy: EmptyApproverPolicy;
  canRejectToStart: boolean;
}
export interface CcProps { memberIds: string[]; enableHandAdd: boolean }
export interface ConditionProps { rules: ConditionRule[]; isDefault: boolean }
export interface StartProps { rangeType: 'ALL' | 'MEMBER' | 'ROLE'; memberIds: string[] }

export type NodeProps = ApproverProps | CcProps | ConditionProps | StartProps | Record<string, never>;

export interface WorkflowNode {
  id: string;                   // crypto.randomUUID()
  name: string;
  type: NodeType;
  props: NodeProps;
  childNode: WorkflowNode | null;         // 主链后继
  conditionNodes?: WorkflowNode[];        // 仅 CONDITIONS：分支列（type=CONDITION）
}

export interface WorkflowDoc {
  name: string;
  updatedAt: number;            // 毫秒时间戳，对齐后端约定
  root: WorkflowNode;           // 根固定为 START
}
```

### 5.2 递归渲染核心（`NodeChain.vue`）

```vue
<script setup lang="ts">
import type { WorkflowNode } from '@/types/workflow'
defineProps<{ node: WorkflowNode | null }>()
</script>

<template>
  <template v-if="node">
    <!-- 条件分支容器：自身不渲染卡片，交给 BranchWrap -->
    <BranchWrap v-if="node.type === 'CONDITIONS'" :container="node" />
    <NodeCard v-else :node="node" @open-drawer="$emit('open-drawer', $event)" />

    <AddNodeButton :parent-node="node" />
    <NodeChain :node="node.childNode" />   <!-- 自递归 -->
  </template>
</template>
```

> `CONDITIONS.childNode` 是所有分支汇合后的主干，由 `BranchWrap` 之后继续向下递归。

### 5.3 关键组件职责

- **`BranchWrap.vue`**：外层相对定位，内部 `flex` 横排分支列（列宽 `260px`）；容器左右两条竖边线 + 列间短横线形成「分流/汇合」四边形视觉效果；右上角「+ 添加条件」；每列头部条件卡片 hover 显示上移/下移（优先级）与删除；`isDefault` 列固定最右、不可删不可移、无规则编辑。
- **`NodeCard.vue`**：props `node`，emits `open-drawer/copy/remove`；按 `type` 从映射表取图标与主色（如 `START→User/#409EFF`、`APPROVER→Avatar/#FF9438`、`CC→Bell/#33B9AC`、`CONDITION→Share/#8A94E6`，图标取自 `@element-plus/icons-vue`）。
- **`AddNodeButton.vue`**：props `parentNode`；菜单选择后调 `store.insertNode(parentId, type)`——新节点插为 `parent.childNode`，原后继挂到新节点之后；parent 为 `CONDITION` 列时插为列链头部。
- **属性抽屉**：`WorkflowDesigner` 持 `activeNode = ref<WorkflowNode | null>(null)`，按类型切换表单；表单**编辑临时副本**（深拷贝 props），「保存」一次性 `updateNodeProps(id, props)` 并重算卡片描述，取消丢弃——避免半成品污染画布。
  - 审批人抽屉：来源 `el-radio-group`、成员多选 `el-select`（一期 mock 数据）、或签/会签、空审批人策略、可退回发起人开关；
  - 条件抽屉：规则行（字段 + 操作符 + 值），行间「且」，支持增删行。

## 6. 状态管理（`src/stores/workflow.ts`）

Pinia **setup store**，画布只读消费、全部变更收敛到 store：

```ts
export const useWorkflowStore = defineStore('workflow', () => {
  const doc = ref<WorkflowDoc>(createDefaultDoc())  // 默认仅 START 根节点
  const zoom = ref(1)                               // 0.5 ~ 2
  const activeNodeId = ref<string | null>(null)

  const activeNode = computed(() =>
    activeNodeId.value ? findNode(doc.value.root, activeNodeId.value) : null)

  function insertNode(parentId: string, type: NodeType): void
  function deleteNode(id: string): void             // parent.childNode = target.childNode 接驳
  function copyNode(id: string): void               // structuredClone 子树 + 重生成全部 id，插到原节点后
  function updateNodeProps(id: string, props: NodeProps, name?: string): void
  function addConditionBranch(containerId: string): void
  function deleteConditionBranch(id: string): boolean  // 仅剩 1 列时返回 false，由 UI 提示
  function moveConditionBranch(id: string, dir: -1 | 1): void  // 与相邻列交换
  function loadDoc(json: string): boolean           // 解析 + 结构校验
  function exportDoc(): string

  return { doc, zoom, activeNodeId, activeNode, /* ...actions */ }
})
```

| 树操作 | 算法（纯递归，无第三方依赖） |
|--------|------------------------------|
| 查找 | 先序：当前 → `childNode` → `conditionNodes[]` |
| 插入 | `newNode.childNode = parent.childNode; parent.childNode = newNode` |
| 删除 | 找到 parent，`parent.childNode = target.childNode`；分支列则数组 splice |
| 复制 | `structuredClone` 后先序遍历重生成 id |

## 7. 交互设计明细

| 场景 | 行为 |
|------|------|
| 「+」添加节点 | 立即插入并**自动打开对应抽屉**（钉钉行为） |
| 删除卡片 ✕ | `ElMessageBox.confirm` 后连同子树删除 |
| 复制 | 深拷贝子树重生成 id，插到当前节点之后 |
| 添加条件列 | 尾插新列并自动打开条件抽屉 |
| 优先级调整 | 条件卡片 hover 上移/下移箭头，与相邻列交换；默认列恒最右 |
| 删除条件列 | 二次确认；删至最后一列时整容器按接驳规则移除 |
| 缩放 | 工具栏 `- / +` 步进 0.1 钳制 [0.5, 2]；「适应画布」按内容宽自适应；Ctrl+滚轮为可选增强 |
| 点击卡片 | 打开抽屉并高亮当前节点（描边 `#409EFF`） |
| 抽屉关闭 | 有未保存改动时 `ElMessageBox.confirm('未保存的修改将丢失')` |

**校验（`useWorkflowValidate.ts`）**：保存前先序遍历产出 `{ nodeId, message }[]`：

1. `APPROVER` 未配置审批人；2. 非默认 `CONDITION` 无规则；3. 节点名称为空。
处理：`ElMessage.error` 汇总条数，首个错误节点自动滚动到视口并描红 3s。
