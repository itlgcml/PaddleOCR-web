## 用户需求
依据 `backend-docs/用户注册与登录功能.md` §9 的接口出入参契约，在 `frontend/`（当前为空白脚手架）生成对应的前端 Vue 代码，覆盖后端里程碑 M5 范围。

## 产品概述
为 PaddleOCR-web 补齐账号体系前端：用户可注册（可选所属机构）、登录获取 JWT 双令牌，系统提供基于角色的访问控制（管理页仅 ADMIN 可见）；登录后进入后台布局，左侧菜单导航，顶部展示用户信息与退出入口。

## 核心功能
- **认证**：登录页（用户名+密码，校验 4~32 位/8~20 位）、注册页（用户名/密码/昵称/邮箱/可选机构下拉——匿名拉取机构树）；登录/注册成功跳首页
- **令牌管理**：accessToken/refreshToken 持久化 localStorage；axios 拦截器自动注入 `Authorization: Bearer`；40102 过期时静默调 `/refresh` 换新并重放原请求（并发 single-flight 防重复刷新）；40100/40101/40103/40023 清 token 跳登录（40023 提示"账号已被禁用"）；40300 提示无权限
- **当前用户**：进入系统调 `/api/auth/me` 刷新用户态；登出调 `/api/auth/logout`（携带 refreshToken 双吊销）后清本地态跳登录
- **路由守卫**：未登录访问受保护页跳 `/login`（带 redirect）；已登录访问 `/login` 跳首页；管理页校验角色含 ADMIN
- **系统设置（ADMIN）**：
  - 机构管理：树形表格展示机构树，新增（父机构下拉+编码/名称/排序）、修改（名称/排序/状态）、删除（错误码 40027/40028 友好提示由拦截器统一弹出）
  - 角色管理：分页表格+关键字搜索，新增/编辑对话框，`builtIn=1` 隐藏编辑删除按钮
  - 用户管理：分页表格+筛选（用户名模糊/机构/状态），调整机构对话框、分配角色对话框（多选全量替换，默认勾选现有角色）、启用/禁用（当前登录用户自己禁操作）
- **视觉**：现代简洁风格，登录/注册为居中卡片式（渐变背景+品牌标识），后台为 Element Plus 经典侧边菜单布局，整体风格统一


## Tech Stack
完全复用现有锁定栈（禁止改版本）：Vue 3.5.43（`<script setup lang="ts">`）+ TypeScript 5.9.3（strict）+ Vite 8.3.0 + Element Plus 2.14.6（unplugin 按需）+ Pinia 4.0.3（setup store）+ Vue Router 4.5.1 + Axios 1.20.0。构建链 `vue-tsc -b && vite build`。

## Implementation Approach
- **分层铁律**：`views → composables/stores → api → types`；组件纯 UI；ID 一律 `string`（后端雪花 Long 已 `ToStringSerializer`）；禁 `any`/`@ts-ignore`/`console.log`/`v-html`
- **契约镜像**：`src/types/api.ts` 定义 `ApiResponse<T>{code,message,data,timestamp:number}`（成功码 **0**，非 200）+ `PageResult<T>{records,total,pageNum,pageSize}` + `PageQuery`；`src/types/auth.ts` 逐字段镜像 §9 全部 VO/DTO（UserInfoVO/LoginVO/TokenVO/OrgBriefVO/OrgTreeVO/RoleVO/RoleBriefVO/UserPageVO 及各 DTO），时间字段为 `string`（`yyyy-MM-dd HH:mm:ss`）
- **唯一 axios 实例** `src/api/request.ts`：
  - `baseURL: import.meta.env.VITE_API_BASE_URL`（`.env.development` 留空走 vite proxy `/api`，`.env.production` 配 `/api`），超时 60s
  - 请求拦截器：从 localStorage 读 accessToken 注入 `Authorization: Bearer <token>`
  - 响应拦截器：`code === 0` 解包返回 `data`；业务失败 `ElMessage.error(message)` + reject
  - **HTTP 401/403 特殊分支**（文档 §9.1.5 前端约定）：从 `error.response.data.code` 取码——`40102` 且持有 refreshToken → single-flight 调 `/api/auth/refresh`（用独立的裸 axios 调用以避免拦截器递归），成功后更新 token 重放原请求；刷新失败或 `40100/40101/40103/40023` → 清 token、提示（40023 提示"账号已被禁用"）、`router.push({name:'Login'})`；`40300` → 提示无权限。并发 401 请求共享同一刷新 Promise，刷新完成后依次重放
- **auth store**（`src/stores/auth.ts`，setup store）：state（accessToken/refreshToken/user），persist token 到 localStorage，actions（login/logout/fetchMe/setTokens/clearAuth）；store 内不调 ElMessage
- **路由**：懒加载 + name 跳转 + `/:pathMatch(.*)*` 兜底；守卫只在 `router/index.ts`，分支全部终止；`meta: { requiresAuth: true, requiresAdmin: true }`
- **API 层按域拆分**：`auth.ts`（register/login/refresh/me/logout）、`org.ts`（tree/create/update/remove）、`role.ts`（page/all/create/update/remove）、`user.ts`（page/assignOrg/assignRoles/updateStatus）；函数 `fetchXxx`/`submitXxx`，显式返回 `Promise<T>`，参数 >2 个封装 interface
- **性能**：机构树全量一次拉取内存组树（后端已组好树直接用）；角色分配下拉用 `/api/roles/all`；分页用 `el-pagination`，页大小变化重置第 1 页；除登录/注册页外的刷新仅一次 single-flight
- **降级保护**：当前空白脚手架无既有 `request.ts`/`router`，按规范从零创建，不破坏现有 `App.vue` 静态欢迎内容（迁移为首页占位）

## 设计风格
现代简洁企业后台风格，Element Plus 组件体系统一承载。登录/注册页：全屏渐变背景（深蓝→青色调），中央白色圆角卡片（阴影+微透明），顶部品牌图标与"PaddleOCR 在线识别"标题，表单居中、按钮主色块级渐变，卡片带轻微淡入动画。后台布局：左侧深色侧边栏（折叠菜单：首页/系统设置-机构/角色/用户），顶栏白色（面包屑+右侧用户头像下拉：用户名/角色标签/退出登录），内容区浅灰背景+白色圆角卡片。管理页：筛选区+操作按钮区+表格+分页的标准节奏；危险操作红色按钮+ElMessageBox 确认；内置角色/禁用自己等按钮按权限隐藏。交互：按钮 loading 态、表格 loading 遮罩、ElMessage 轻提示、对话框关闭重置校验。
