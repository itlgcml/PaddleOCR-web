## 用户需求
为「律所选聘」业务模块生成前后端代码齐全的增删改查功能：
- 数据字段：标题（必填）、选聘金额（必填）、选聘原因（必填）
- 后端：新建以「律所选聘」英文名命名的包（`lawfirmselect`），生成完整分层代码
- 前端：同样新建一个文件夹（`views/lawfirmselect/`），生成管理页面

## 需求澄清与既定假设
1. 模块英文命名 `lawfirmselect`，与现有路由 `business/law-firm-select`、菜单「律所选聘」保持一致；接口路径用 `/api/law-firm-select`（kebab-case）。
2. 用户提及的 `views/business/ContractSignView.vue` 为位置参考（合同签订是另一模块，保持不动）；`views/business/LawFirmSelectView.vue` 是现有空占位页，将被新文件夹下的实现页取代，路由 import 同步更新。
3. 权限沿用现有业务路由约定：登录即可访问（不加 ADMIN 限制），与 SecurityConfig 中 `/api/**` 默认 authenticated 一致，无需改动安全配置。
4. 默认不执行 mvn/npm 构建、测试、联调命令。

## 核心功能
- 分页列表：按标题前缀匹配搜索，表格展示标题/选聘金额/选聘原因/创建时间
- 新增：弹窗表单（标题、金额、原因均有必填与长度校验）
- 修改：弹窗表单回填，全字段可改
- 删除：二次确认，逻辑删除；当前页删空自动回退一页
- 菜单入口已存在（BasicLayout `/business/law-firm-select`），无需改动

## 实现方案
以现有角色模块（RoleController/RoleService/RoleServiceImpl/RoleManageView）为样板，复制一套完整的单表 CRUD 分层实现：DDL → DO/Mapper（ocr-dal）→ DTO/VO/Service（ocr-service，model 包按现有约定平铺放 dto/vo 目录）→ Controller（新建 `controller.lawfirmselect` 包）→ 前端 types/api/新文件夹视图 → 路由指向调整。关键技术决策：
- 表名 `law_firm_select`，雪花 ID（`IdType.ASSIGN_ID`）+ 逻辑删除（`@TableLogic`）+ 审计字段自动填充（复用 `AuditMetaObjectHandler`，业务代码禁止手动 set 时间）
- 金额用 `DECIMAL(12,2)` / `BigDecimal`，校验 `@NotNull + @DecimalMin("0.01") + @Digits(10,2)`
- 搜索按项目规约统一前缀匹配（`likeRight`，严禁左模糊），按 `createTime` 倒序分页
- 新增/修改共用一个 `LawFirmSelectSaveDTO`（全字段可改、无禁改字段，避免重复定义）
- `id` 前后端契约：Long 雪花 ID 经 `ToStringSerializer` 序列化为 string，前端一律 string
- Mapper 用 `@Mapper` 注解自动注册，无 XML、无 MapperScan 改动；权限走 `/api/**` 默认 authenticated，SecurityConfig 零改动
- 性能：单表分页走索引（PK + idx_create_time），无 N+1，无关联查询

## 接口契约（与 OrgController/RoleController 风格一致）
- `GET /api/law-firm-select/page?pageNum=&pageSize=&title=` → `ApiResponse<PageResultVO<LawFirmSelectVO>>`
- `POST /api/law-firm-select/create`（body: LawFirmSelectSaveDTO）→ `ApiResponse<String>`（新记录 id）
- `PUT /api/law-firm-select/update/{id}`（body: LawFirmSelectSaveDTO）→ `ApiResponse<Void>`
- `DELETE /api/law-firm-select/delete/{id}` → `ApiResponse<Void>`
- 新增错误码（ResultCode 律所选聘域）：`LAW_FIRM_SELECT_NOT_FOUND(40050, "律所选聘记录不存在")`

## DDL（backend/sql/04-lawfirmselect-schema.sql，对齐 02/03 文件风格）
```sql
-- 04-lawfirmselect-schema.sql
-- 律所选聘记录表 DDL
-- 适用：MySQL 5.7+ / utf8mb4；无物理外键
CREATE TABLE law_firm_select (
    id          BIGINT        NOT NULL COMMENT '雪花 ID',
    title       VARCHAR(128)  NOT NULL COMMENT '标题',
    amount      DECIMAL(12,2) NOT NULL COMMENT '选聘金额（元）',
    reason      VARCHAR(512)  NOT NULL COMMENT '选聘原因',
    create_time DATETIME      NOT NULL COMMENT '创建时间',
    update_time DATETIME      NOT NULL COMMENT '更新时间',
    deleted     TINYINT       NOT NULL DEFAULT 0 COMMENT '逻辑删除 0=未删 1=已删',
    PRIMARY KEY (id),
    KEY idx_create_time (create_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='律所选聘记录表';
```

## 设计说明
新页面与现有系统管理页保持完全一致的视觉语言（复用 RoleManageView 的结构与样式），确保后台整体统一。

页面自上而下分块：
1. **页面卡片**：白色圆角 12px 阴影卡片铺满内容区，统一页面底色；
2. **顶部工具栏**：左侧标题搜索框（280px、带搜索图标、回车/清空触发）、右侧「刷新」+蓝色主按钮「新增选聘」；
3. **数据表格**：序号、标题、选聘金额（右对齐、千位格式化两位小数）、选聘原因（超长省略 tooltip）、创建时间、操作（编辑/删除文字按钮）；空态用 el-empty；
4. **分页条**：右下角，背景分页器，支持 10/20/50 每页与跳页；
5. **新增/编辑弹窗**：480px 宽，label-width 88px；标题单行输入、选聘金额数字输入（精度 2）、选聘原因多行文本（3 行、512 字计数）；编辑时字段全量回填；
6. **删除确认**：ElMessageBox warning 弹窗，提示标题名称。

交互细节：按钮 loading 态防重复提交、删除后当前页删空自动回退一页、搜索重置页码为 1。
